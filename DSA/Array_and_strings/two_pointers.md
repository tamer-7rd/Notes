# Два указателя (Two Pointers)

**Два указателя** — это чрезвычайно распространённая техника для решения задач на массивы и строки. Суть в том, что используются две целочисленные переменные, которые оба движутся вдоль итерируемой структуры. В этой статье мы фокусируемся на массивах и строках, поэтому у нас будет два целых числа — как правило `i` и `j`, или `left` и `right` — каждое из которых представляет индекс массива или строки.

### Метод 1: Указатели с краёв, движущиеся навстречу друг другу

> Поставить указатели на края входных данных. Двигать их навстречу друг другу, пока они не встретятся.

**Алгоритм:**
1. Поставить один указатель на первый индекс `0`, другой — на последний `input.length - 1`.
2. Использовать цикл `while`, пока указатели не сравняются.
3. На каждой итерации цикла двигать указатели навстречу: увеличивать левый, уменьшать правый, или оба. Выбор зависит от задачи.

**Псевдокод:**
```
function fn(arr):
    left = 0
    right = arr.length - 1

    while left < right:
        // логика в зависимости от задачи
        // выбрать одно из:
        1. left++
        2. right--
        3. оба left++ и right--
```

**Сложность:** Этот алгоритм никогда не выполнит более $O(n)$ итераций цикла, так как указатели стартуют на расстоянии $n$ друг от друга и на каждом шаге сближаются минимум на один шаг. При $O(1)$ работе внутри цикла — итоговая сложность $O(n)$, что обычно является наилучшим возможным результатом.

### Пример 1: Проверка палиндрома

**Задача:** Дана строка `s`, вернуть `true`, если она является палиндромом, иначе `false`.

Строка является палиндромом, если она читается одинаково слева направо и справа налево. После обращения строки первый символ становится последним. Можно использовать два указателя, чтобы проверить, что все соответствующие символы равны.

```python
def check_if_palindrome(s):
    left = 0
    right = len(s) - 1

    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1

    return True
```

> Если бы вместо строки был массив символов, алгоритм не изменился бы — техника двух указателей работает, пока индексные переменные движутся вдоль некоторого абстрактного итерируемого объекта.

Алгоритм очень эффективен: работает за $O(n)$ и использует лишь $O(1)$ памяти (всего два целочисленных переменных). Временная сложность $O(n)$, так как цикл выполняет не более $n$ итераций.

### Пример 2: Два числа с заданной суммой (отсортированный массив)

**Задача:** Дан **отсортированный** массив уникальных целых чисел `nums` и целевое число `target`. Вернуть `true`, если существует пара чисел с суммой равной `target`, иначе `false`.

*Похожая задача на LeetCode: 167. Two Sum II - Input Array Is Sorted.*

**Перебором:** каждое число можно сочетать с любым другим, что даёт $O(n^2)$. Но так как массив отсортирован, можно улучшить до $O(n)$ с помощью двух указателей.

**Как работает:** Начинаем с первого и последнего чисел. Их сумма: $1 + 15 = 16$. Поскольку $16 > \text{target}$, нужно уменьшить сумму — двигаем правый указатель. Далее $1 + 14 = 15 > \text{target}$ — снова вправо. $1 + 9 = 10 < \text{target}$ — двигаем левый указатель. $2 + 9 = 11 < \text{target}$ — снова левый. $4 + 9 = 13 = \text{target}$.

**Почему это работает:** Массив отсортирован, поэтому движение левого указателя вправо увеличивает значение (`nums[left] → x`), а движение правого влево уменьшает (`nums[right] → y`). Если $x + y > \text{target}$, то нельзя найти решение с данным `y`, так как `x` может только расти. Аналогично для `x`.

```python
def check_for_target(nums, target):
    left = 0
    right = len(nums) - 1

    while left < right:
        # curr — текущая сумма
        curr = nums[left] + nums[right]
        if curr == target:
            return True
        if curr > target:
            right -= 1
        else:
            left += 1

    return False
```

Алгоритм использует $O(1)$ памяти и имеет временную сложность $O(n)$.

### Метод 2: Два указателя на двух итерируемых объектах

> Двигаться по двум входным данным одновременно, пока все элементы не будут проверены.

**Алгоритм:**
1. Создать два указателя, по одному для каждого итерируемого объекта. Каждый начинается с первого индекса.
2. Использовать цикл `while`, пока один из указателей не достигнет конца своего итерируемого объекта.
3. На каждой итерации двигать указатели вперёд — увеличивать один или оба в зависимости от задачи.
4. Так как цикл остановится, когда один из указателей достигнет конца, второй может ещё не быть в конце. Если нужно — дописать дополнительные циклы для оставшихся элементов.

**Псевдокод:**
```
function fn(arr1, arr2):
    i = j = 0
    while i < arr1.length AND j < arr2.length:
        // логика в зависимости от задачи
        // выбрать одно из:
        1. i++
        2. j++
        3. оба i++ и j++

    // Шаг 4: убедиться, что оба итерируемых объекта исчерпаны
    // Только один из этих циклов выполнится
    while i < arr1.length:
        // логика
        i++

    while j < arr2.length:
        // логика
        j++
```

Аналогично первому методу, этот метод имеет линейную временную сложность $O(n + m)$ при $O(1)$ работе внутри цикла, где `n = arr1.length` и `m = arr2.length`. На каждой итерации хотя бы один указатель движется вперёд, а суммарно они не могут сделать более $n + m$ шагов.

### Пример 3: Слияние двух отсортированных массивов

**Задача:** Даны два отсортированных целочисленных массива `arr1` и `arr2`. Вернуть новый массив, который объединяет оба и тоже является отсортированным.

Можно объединить оба массива, а затем отсортировать — это $O((n + m) \cdot \log(n + m))$. Но раз массивы уже отсортированы, можно воспользоваться техникой двух указателей и улучшить до $O(n + m)$.

Строим итоговый массив `ans` поэлементно. Начинаем оба указателя с первого индекса. На каждой итерации — два значения. То, которое меньше, должно идти первым в ответе — добавляем его и двигаем соответствующий указатель.

```python
def combine(arr1, arr2):
    ans = []
    i = j = 0

    while i < len(arr1) and j < len(arr2):
        if arr1[i] < arr2[j]:
            ans.append(arr1[i])
            i += 1
        else:
            ans.append(arr2[j])
            j += 1

    while i < len(arr1):
        ans.append(arr1[i])
        i += 1

    while j < len(arr2):
        ans.append(arr2[j])
        j += 1

    return ans
```

Как и в предыдущих примерах, алгоритм имеет временную сложность $O(n + m)$ и использует $O(1)$ дополнительной памяти (не считая выходного массива).

### Пример 4: Является ли строка подпоследовательностью?

**Задача:** Даны две строки `s` и `t`. Вернуть `true`, если `s` является подпоследовательностью `t`, иначе `false`.

*LeetCode: 392. Is Subsequence.*

**Подпоследовательность** строки — это последовательность символов, полученная удалением некоторых (или ни одного) символов из исходной строки с сохранением относительного порядка оставшихся. Например, `"ace"` является подпоследовательностью `"abcde"`, а `"aec"` — нет.

Нужно проверить, что символы `s` встречаются в `t` в том же порядке. Если `s[i] == t[j]` — мы «нашли» букву на позиции `i` и переходим к следующей (`i++`). `j` увеличиваем на каждой итерации всегда. `s` является подпоследовательностью `t`, если `i == s.length` в конце.

```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        i = j = 0
        while i < len(s) and j < len(t):
            if s[i] == t[j]:
                i += 1
            j += 1

        return i == len(s)
```

Как и все предыдущие примеры, алгоритм использует $O(1)$ памяти. Временная сложность линейна относительно длин `s` и `t`.

### Заключение

Помните, что приведённые методы — лишь ориентиры. Например, в первом методе мы ставили указатели на первый и последний индексы, но иногда задача требует начинать с разных позиций. Во втором — двигали два указателя вперёд по двум входным данным, но иногда будет лишь один входной массив, и оба указателя начнут с первого индекса.

**Два указателя** — это просто идея использования двух целочисленных переменных для движения вдоль итерируемых объектов. Это абстрактная концепция — следите за нестандартными вариантами применения. Существуют даже задачи, использующие три указателя.
