# Два указателя (Two Pointers)

Формат этой статьи — это формат, который будут иметь многие статьи в этом курсе. Мы будем вводить идеи, а затем проходить примеры задач, чтобы продемонстрировать некоторые идеи. Эти разобранные задачи не предназначены для того, чтобы вы решали их самостоятельно.

**Два указателя** — это чрезвычайно распространённая техника для решения задач на массивы и строки. Суть в том, что используются две целочисленные переменные, которые оба движутся вдоль итерируемой структуры. В этой статье мы фокусируемся на массивах и строках, поэтому у нас будет два целых числа — как правило `i` и `j`, или `left` и `right` — каждое из которых представляет индекс массива или строки.

### Метод 1: Указатели с краёв, движущиеся навстречу друг другу

> Поставить указатели на края входных данных. Двигать их навстречу друг другу, пока они не встретятся.

**Алгоритм:**
1. Поставить один указатель на первый индекс `0`, другой — на последний `input.length - 1`.
2. Использовать цикл `while`, пока указатели не сравняются.
3. На каждой итерации цикла двигать указатели навстречу: увеличивать левый, уменьшать правый, или оба. Выбор зависит от задачи.

**Псевдокод:**
```
function fn(arr):
    left = 0
    right = arr.length - 1

    while left < right:
        // логика в зависимости от задачи
        // выбрать одно из:
        1. left++
        2. right--
        3. оба left++ и right--
```

**Сложность:** Этот алгоритм никогда не выполнит более $O(n)$ итераций цикла, так как указатели стартуют на расстоянии $n$ друг от друга и на каждом шаге сближаются минимум на один шаг. При $O(1)$ работе внутри цикла — итоговая сложность $O(n)$, что обычно является наилучшим возможным результатом.

### Пример 1: Проверка палиндрома

**Задача:** Дана строка `s`, вернуть `true`, если она является палиндромом, иначе `false`.

Строка является палиндромом, если она читается одинаково слева направо и справа налево. Это означает, что после переворота (реверса) строка остаётся точно такой же (например, `"abcdcba"` или `"racecar"`).

После переворота строки первый символ становится последним. Если строка после реверса не изменилась, значит, её первый символ равен последнему, второй символ — предпоследнему и так далее. Мы можем применить технику двух указателей, чтобы проверить равенство всех соответствующих пар символов:
- Сначала сравниваем первый и последний символы, используя два отдельных указателя.
- Для проверки следующей пары символов сдвигаем указатели навстречу друг другу на одну позицию (`left += 1`, `right -= 1`).
- Продолжаем до тех пор, пока указатели не встретятся или пока не обнаружится несовпадение.

```python
def check_if_palindrome(s):
    left = 0
    right = len(s) - 1

    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1

    return True
```

> **Примечание:** Если бы на вход подавался массив символов вместо строки, алгоритм ничуть не изменился бы. Техника двух указателей работает для любого абстрактного итерируемого объекта, по которому могут перемещаться индексные переменные.

Алгоритм крайне эффективен: он работает за **$O(n)$** и требует всего **$O(1)$** дополнительной памяти. Каким бы большим ни был ввод, используются всего две целочисленные переменные. Временная сложность — $O(n)$, поскольку каждая итерация цикла `while` выполняется за $O(1)$, а общее число итераций не превышает $n$ (указатели стартуют на расстоянии $n$ и с каждым шагом сближаются минимум на единицу).

### Пример 2: Два числа с заданной суммой (отсортированный массив)

**Задача:** Дан **отсортированный** массив уникальных целых чисел `nums` и целевое число `target`. Вернуть `true`, если существует пара чисел с суммой равной `target`, иначе `false`.

*(Эта задача похожа на классическую Two Sum, но в оригинальной Two Sum входной массив не отсортирован).*

Например, дано:
```python
nums = [1, 2, 4, 6, 8, 9, 14, 15]
target = 13
```
Вернуть `true`, потому что $4 + 9 = 13$.

*Похожая задача на LeetCode: [167. Two Sum II - Input Array Is Sorted](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/).*

**Наивный подход (Brute Force):** перебрать все возможные пары чисел. Каждый элемент может быть спарен с любым другим, что дает временную сложность $O(n^2)$, где $n$ — длина массива. Но так как массив **отсортирован**, с помощью двух указателей мы можем улучшить сложность до **$O(n)$**.

**Пошаговый разбор:** Начинаем с крайних элементов. Их сумма: $1 + 15 = 16$.
- Так как $16 > \text{target}$, нам нужно уменьшить текущую сумму — для этого сдвигаем правый указатель влево (`right -= 1`).
- Теперь сумма: $1 + 14 = 15 > \text{target}$ — снова сдвигаем правый указатель влево.
- Теперь сумма: $1 + 9 = 10 < \text{target}$. Сумма слишком мала, нужно её увеличить — сдвигаем левый указатель вправо (`left += 1`).
- Теперь сумма: $2 + 9 = 11 < \text{target}$ — снова сдвигаем левый указатель вправо.
- Наконец: $4 + 9 = 13 = \text{target}$ — пара найдена, возвращаем `true`.

**Почему это работает:** Поскольку массив отсортирован, сдвиг левого указателя вправо необратимо увеличивает значение, на которое он указывает (`nums[left] = x`). Аналогично, сдвиг правого указателя влево необратимо уменьшает значение (`nums[right] = y`).
- Если $x + y > \text{target}$, то с текущим $y$ решение уже невозможно найти, так как $x$ может только расти. Значит, решение (если оно есть) возможно только при уменьшении $y$ (сдвиг правого указателя).
- Та же логика применима и к $x$: если $x + y < \text{target}$, пара с текущим $x$ невозможна (ведь $y$ может только уменьшаться), поэтому нужно увеличивать $x$ (сдвиг левого указателя).

```python
def check_for_target(nums, target):
    left = 0
    right = len(nums) - 1

    while left < right:
        # curr — текущая сумма
        curr = nums[left] + nums[right]
        if curr == target:
            return True
        if curr > target:
            right -= 1
        else:
            left += 1

    return False
```

Как и в предыдущем примере, этот алгоритм использует **$O(1)$** дополнительной памяти и работает за линейное время **$O(n)$**.

### Метод 2: Одновременный обход двух итерируемых объектов

Метод, когда мы начинаем с первого и последнего индексов и двигаем указатели навстречу друг другу — лишь один из способов реализации двух указателей. Вся прелесть алгоритмов заключается в их абстрактности: «два указателя» — это просто концепция, которую можно воплотить множеством различных способов.

Следующий метод применяется, когда задача содержит **два итерируемых объекта** во входных данных (например, два массива или две строки):

> Двигаться по обоим входным объектам одновременно, пока не будут проверены все элементы.

**Алгоритм:**
1. Создать два указателя, по одному для каждого итерируемого объекта. Каждый указатель начинает с первого индекса (`0`).
2. Использовать цикл `while`, пока хотя бы один из указателей не достигнет конца своего объекта.
3. На каждой итерации цикла двигать указатели вперёд — увеличивать один из них или оба в зависимости от логики задачи.
4. Поскольку цикл `while` завершится, как только один из указателей дойдет до конца, второй указатель к этому моменту ещё не закончит свой обход. Если для решения требуется гарантированно обработать абсолютно все элементы, необходимо дописать дополнительный код (циклы), чтобы исчерпать оставшиеся элементы.

**Псевдокод:**
```
function fn(arr1, arr2):
    i = j = 0
    while i < arr1.length AND j < arr2.length:
        // некоторая логика в зависимости от задачи
        // выбор одного из действий:
        1. i++
        2. j++
        3. оба i++ и j++

    // Шаг 4: убедиться, что оба объекта полностью исчерпаны
    // Обратите внимание: выполнится максимум один из этих циклов
    while i < arr1.length:
        // логика
        i++

    while j < arr2.length:
        // логика
        j++
```

**Сложность:**
Аналогично первому методу, данный подход имеет линейную временную сложность **$O(n + m)$**, если операции внутри цикла выполняются за $O(1)$ (где $n = \text{arr1.length}$, а $m = \text{arr2.length}$). Это обусловлено тем, что на каждой итерации хотя бы один указатель сдвигается на шаг вперёд, а суммарно указатели не могут сдвинуться более $n + m$ раз до полного исчерпания массивов.

### Пример 3: Слияние двух отсортированных массивов

**Задача:** Даны два отсортированных целочисленных массива `arr1` и `arr2`. Вернуть новый массив, который объединяет все их элементы и также является отсортированным.

Например:
- `arr1 = [1, 4, 7, 20]`
- `arr2 = [3, 5, 6]`
- Результат: `[1, 3, 4, 5, 6, 7, 20]`

**Тривиальный подход:** объединить оба массива в один общий и применить встроенную сортировку. Если общая длина $n = \text{arr1.length} + \text{arr2.length}$, то сложность сортировки составит $O(n \log n)$. Это было бы хорошим решением для неотсортированных данных, но так как массивы уже упорядочены, мы можем задействовать технику двух указателей и улучшить время работы до **$O(n + m)$** (или $O(n)$, где $n$ — суммарная длина).

> **Замечание о Big O переменных:** В предыдущем примере мы обозначили $n = \text{arr1.length}$ и $m = \text{arr2.length}$. Здесь мы говорим $n = \text{arr1.length} + \text{arr2.length}$. Почему мы изменили обозначение? В анализе Big O мы вольны определять переменные так, как считаем удобным. Можно было оставить $n$ и $m$: тогда сортировка стоила бы $O((n + m) \log(n + m))$, а подход с указателями — $O(n + m)$. Поскольку мы объединяем массивы, суммарная длина является ключевой величиной, и логично обозначить её одной переменной $n$. Оба способа записи корректны.

**Решение с двумя указателями:**
Мы формируем массив ответа `ans`, добавляя по одному элементу за раз. Устанавливаем оба указателя на начало каждого массива. На каждом шаге сравниваем два текущих элемента: тот, который меньше, должен стоять раньше в ответе — добавляем его в `ans` и сдвигаем соответствующий указатель.

```python
def combine(arr1, arr2):
    # ans — результирующий массив (ans is the answer)
    ans = []
    i = j = 0

    while i < len(arr1) and j < len(arr2):
        if arr1[i] < arr2[j]:
            ans.append(arr1[i])
            i += 1
        else:
            ans.append(arr2[j])
            j += 1

    # Добираем оставшиеся элементы из arr1 (если остались)
    while i < len(arr1):
        ans.append(arr1[i])
        i += 1

    # Добираем оставшиеся элементы из arr2 (если остались)
    while j < len(arr2):
        ans.append(arr2[j])
        j += 1

    return ans
```

Как и в предыдущих задачах, алгоритм работает за линейное время **$O(n + m)$** и использует **$O(1)$** дополнительной памяти (если не учитывать память под результирующий массив `ans`, что является стандартной практикой анализа).

### Пример 4: Является ли строка подпоследовательностью?

**Задача:** Даны две строки `s` и `t`. Вернуть `true`, если `s` является подпоследовательностью `t`, иначе `false`.

*LeetCode: [392. Is Subsequence](https://leetcode.com/problems/is-subsequence/).*

**Подпоследовательность (Subsequence)** строки — это новая последовательность символов, полученная из исходной строки путём удаления некоторого количества (или ни одного) символов без изменения относительного порядка оставшихся символов.
- Например, `"ace"` является подпоследовательностью `"abcde"`.
- А `"aec"` **не** является подпоследовательностью `"abcde"` (нарушен порядок букв).

В этой задаче нам нужно убедиться, что все символы строки `s` присутствуют в `t` в том же порядке, **с возможными пропусками (gaps allowed)**. То, что они не идут подряд (как в подстроке / substring), не имеет значения.

**Решение двумя указателями:**
- Если `s[i] == t[j]`, значит, мы «нашли» текущий символ строки `s` в `t` и можем двигаться к следующему искомому символу, увеличивая `i` (`i += 1`).
- Указатель `j` мы увеличиваем на каждой итерации в любом случае (`j += 1`), так как символ из `t` уже рассмотрен (это также означает, что данный алгоритм можно легко записать через цикл `for` по строке `t`).
- Строка `s` является подпоследовательностью `t`, если мы смогли найти все её символы, то есть в конце `i == len(s)`.

```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        i = j = 0
        while i < len(s) and j < len(t):
            if s[i] == t[j]:
                i += 1
            j += 1

        return i == len(s)
```

Как и во всех предыдущих примерах, алгоритм использует **$O(1)$** дополнительной памяти, а временная сложность линейна относительно длин строк `s` и `t` — **$O(n)$**, где $n$ — длина строки `t` (в худшем случае $O(\text{len}(s) + \text{len}(t))$).

### Заключение (Closing Notes)

Помните, что приведенные методы — это гибкие ориентиры, а не жесткие рамки:
- В первом методе указатели начинались с первого и последнего индексов, но в других задачах начальные позиции могут отличаться.
- Во втором методе два указателя двигались по двум разным входным массивам. Однако в других задачах может быть всего **один** входной массив/строка, где оба указателя стартуют с начала (например, быстрый и медленный указатели / slow and fast pointers).
- Суть паттерна **Two Pointers** сводится к использованию двух целочисленных индексных переменных для движения по итерируемым объектам. Существуют даже задачи, использующие **три указателя** ("three pointers").
- Материалы курса выстроены по нарастающей: техники из ранних глав будут постоянно использоваться в последующих темах. Двух указателей мы ещё неоднократно коснёмся в дальнейшем.
