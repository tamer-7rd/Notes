# Sliding Window

> Как и два указателя, скользящее окно работает одинаково с массивами и строками — важно лишь то, что они являются итерируемыми объектами. Для краткости, первая часть этой статьи вплоть до примеров будет сосредоточена на **массивах**. Однако вся логика идентична для строк.

Скользящее окно — это ещё один распространённый подход к решению задач, связанных с массивами. Скользящее окно на самом деле реализуется с помощью двух указателей! Прежде чем начать, нам нужно поговорить о концепции **подмассива (subarray)**.

## Подмассивы (Subarrays)

Для данного массива **подмассив** — это непрерывная секция массива. Все элементы должны быть смежными друг с другом в исходном массиве и в их исходном порядке. Например, для массива `[1, 2, 3, 4]` подмассивы (сгруппированные по длине) следующие:

- Подмассивы длины 1: `[1]`, `[2]`, `[3]`, `[4]`
- Подмассивы длины 2: `[1, 2]`, `[2, 3]`, `[3, 4]`
- Подмассивы длины 3: `[1, 2, 3]`, `[2, 3, 4]`
- Подмассивы длины 4: `[1, 2, 3, 4]`

**Подмассив можно определить двумя индексами — началом и концом**. Например, для `[1, 2, 3, 4]` подмассив `[2, 3]` имеет начальный индекс `1` и конечный индекс `2`. Назовём начальный индекс **левой границей (left bound)**, а конечный индекс — **правой границей (right bound)**. Другое название подмассива в этом контексте — "окно" (window).

> **Подмассив (Subarray):** непрерывная секция массива
> Может быть описан левой и правой границей
>
> Массив: `[3, 6, 2, 8, 1, 4, 1, 5]`
> Подмассив: `[2, 8, 1, 4]` → `left = 2`, `right = 5`

## "Валидные" подмассивы

Распространённый паттерн, который вы встретите в задачах на массивы, связан с идеей "валидного" подмассива. Описание задачи будет явно или неявно определять, что делает подмассив "валидным". Мы можем разбить это на две части:

1. **Метрика ограничения (constraint metric)**. Это атрибут подмассива. — Например, сумма подмассива, количество уникальных элементов в подмассиве, частота определённого элемента и т.д.
2. **Числовое ограничение (numeric restriction)** на метрику ограничения.

Например, допустим, задача объявляет подмассив валидным, если его сумма меньше или равна `10`. Метрика ограничения здесь — это сумма подмассива, а числовое ограничение — `<= 10`. Подмассив считается валидным, если его метрика ограничения соответствует числовому ограничению, т.е. сумма меньше или равна `10`.

## Идея

Скользящее окно используется для анализа и нахождения валидных подмассивов массива. Идея скользящего окна заключается в поддержании двух переменных — `left` и `right`. В любой момент времени `left` представляет левую границу нашего окна, а `right` — правую границу нашего окна. Помните, что "окно" здесь — это просто другое слово для подмассива.

Изначально мы устанавливаем `left = right = 0`, что означает, что первое окно, которое мы рассматриваем, — это просто первый элемент массива сам по себе. Мы хотим расширить размер нашего "окна", и мы делаем это, увеличивая `right`. Когда мы увеличиваем `right`, это как "добавление" нового элемента в наше окно.

Но что если после добавления нового элемента подмассив становится невалидным? Например, допустим, добавление нового элемента справа делает сумму подмассива слишком большой. Нам нужно "удалить" некоторые элементы из нашего окна, пока оно снова не станет валидным. Чтобы "удалить" элементы, мы можем увеличить `left`, что сужает наше окно.

> Помните: `left` и `right` представляют границы нашего окна в любой момент времени, поэтому увеличение `left` эквивалентно удалению самого левого элемента.

По мере того как мы добавляем и удаляем элементы, мы "скользим" нашим окном вдоль входных данных. Размер окна постоянно меняется — оно растёт настолько, насколько может, пока не станет невалидным, а затем сжимается, пока снова не станет валидным. Однако оно всегда скользит вправо, пока не достигнет конца входных данных.

> **Добавляем элементы справа и удаляем слева**
> Окно медленно скользит вдоль входных данных
>
> `[3, 6, 2, 8, 1, 4, 1, 5]` — окно сдвигается вправо, расширяясь и сужаясь

Чтобы объяснить, почему этот алгоритм работает, давайте рассмотрим конкретный пример. Допустим, нам дан массив положительных целых чисел `nums` и целое число `k`. Нам нужно найти длину самого длинного подмассива, сумма которого меньше или равна `k`. Для этого примера пусть `nums = [3, 2, 1, 3, 1, 1]` и `k = 5`.

Изначально у нас `left = right = 0`, поэтому наше окно — это только первый элемент: `[3]`. Теперь давайте расширяться вправо, пока ограничение не будет нарушено. Это произойдёт когда `left = 0, right = 2`, и наше окно будет: `[3, 2, 1]`. Сумма здесь равна `6`, что больше `k`. Мы должны теперь сужать окно слева, пока ограничение не перестанет быть нарушенным. После удаления одного элемента окно снова становится валидным: `[2, 1]`.

Почему правильно удалить эту `3` и забыть о ней на оставшуюся часть алгоритма? Потому что входные данные содержат только положительные целые числа, более длинный подмассив напрямую означает бо́льшую сумму. Мы знаем, что `[3, 2, 1]` уже даёт слишком большую сумму. Нет никакой возможности снова получить валидное окно, если мы оставим эту `3`, потому что если мы добавим ещё элементы справа, сумма только увеличится, и мы не можем включить `3` без включения `2` или `1`, так как это нарушило бы определение подмассива. Вот почему мы можем забыть о `3` на оставшуюся часть алгоритма.

## Решение задач с помощью скользящего окна

Когда вы видите задачу, которая не только описывает подмассивы как "валидные", но и просит вас найти эти подмассивы, вы должны сразу думать о скользящем окне.

Часто задача будет просить вас найти **лучший** валидный подмассив. Задача определит, что делает один подмассив **лучше** другого. Например, задача может попросить вас найти **самый длинный** валидный подмассив.

Другой распространённый тип задач — это задачи, которые просят найти количество валидных подмассивов. Мы рассмотрим этот тип задач подробнее позже в статье.

Вот превью некоторых примеров задач, которые мы рассмотрим в этой статье, чтобы помочь вам лучше понять, как выглядят задачи на скользящее окно:

- Найти самый длинный подмассив с суммой, меньшей или равной `k` (метрика ограничения = сумма)
- Найти самую длинную подстроку, содержащую не более одного `"0"` (метрика ограничения = количество нулей)
- Найти количество подмассивов, произведение которых меньше `k` (метрика ограничения = произведение)

## Реализация

Теперь, когда у вас есть представление о том, как работает скользящее окно, давайте поговорим о том, как его реализовать. Для этого раздела мы будем использовать предыдущий пример (найти самый длинный подмассив с суммой, меньшей или равной `k`).

Во-первых, нам нужно определить **метрику ограничения (constraint metric)**. В нашем примере метрика ограничения — это сумма окна. Как нам отслеживать сумму окна по мере добавления и удаления элементов? Один способ — хранить окно в отдельном массиве. Когда мы добавляем элементы справа, мы добавляем их в наш массив. Когда мы удаляем элементы слева, мы удаляем соответствующие элементы из массива. Таким образом, мы всегда можем найти сумму нашего текущего окна, просто просуммировав элементы в отдельном массиве.

Это очень неэффективно, так как удаление элементов и нахождение суммы окна будет стоить O(n) операций. Можно ли лучше?

Нам на самом деле не нужно хранить окно в отдельном массиве. Всё, что нам нужно — это некоторая переменная, назовём её `curr`, которая отслеживает текущую сумму. Когда мы добавляем новый элемент справа, мы просто делаем `curr += nums[right]`. Когда мы удаляем элемент слева, мы просто делаем `curr -= nums[left]`. Таким образом, все операции выполняются за O(1).

> Обратите внимание, что наше окно существует только как идея. Мы не поддерживаем его буквально в виде массива. Нам нужны только `left` и `right`, чтобы помнить его границы, и `curr` для отслеживания метрики ограничения.

Далее, как мы двигаем указатели `left` и `right`? Помните, мы хотим продолжать расширять наше окно, и окно всегда скользит вправо — оно просто может сужаться несколько раз по пути. Поскольку `right` всегда движется вперёд, мы можем использовать цикл for для итерации `right` по входным данным. В каждой итерации цикла for мы будем добавлять элемент `nums[right]` в наше окно.

А что насчёт `left`? Когда мы двигаем `left`, мы сужаем наше окно. Мы сужаем окно только тогда, когда оно становится невалидным. Поддерживая `curr`, мы можем легко определить, валидно ли текущее окно, просто проверив его значение. Если `curr > k`, окно невалидно.

Допустим, `nums = [1, 1, 1, 3]` и `k = 3`. Когда мы доходим до `3` и добавляем её в окно, окно становится невалидным, и `curr` будет равен `6`. Нам нужно удалить три элемента слева, прежде чем окно снова станет валидным.

Это подсказывает, что мы должны использовать цикл while для выполнения удалений. Условие будет `while curr > k` ("пока окно невалидно"). Для выполнения удалений мы делаем `curr -= nums[left]` и затем увеличиваем `left` в каждой итерации цикла while.

Теперь у нас есть систематический способ скольжения окна по входным данным с сохранением его валидности. Как нам обновлять ответ? В каждой итерации цикла for, после цикла while, мы знаем, что текущее окно валидно. Мы можем написать код здесь для обновления ответа. Формула длины окна — `right - left + 1` (запомните эту формулу).

Вот псевдокод, который объединяет всё вместе:

```
function fn(nums, k):
    left = 0
    curr = 0
    answer = 0
    for (int right = 0; right < nums.length; right++):
        curr += nums[right]
        while (curr > k):
            curr -= nums[left]
            left++

        answer = max(answer, right - left + 1)

    return answer
```

## Почему скользящее окно эффективно?

Сколько подмассивов существует для любого массива? Если массив имеет длину `n`, то существует `n` подмассивов длины `1`. Затем `n - 1` подмассивов длины `2` (каждый индекс, кроме последнего, может быть начальным), `n - 2` подмассивов длины `3` и так далее, пока не останется только `1` подмассив длины `n`. Это означает, что всего существует ∑k=1..n k = n·(n+1)/2 подмассивов (это частичная сумма этого ряда).

С точки зрения временной сложности, любой алгоритм, который рассматривает каждый подмассив, будет как минимум O(n²), что обычно слишком медленно. Скользящее окно гарантирует максимум 2n итераций окна — правый указатель может сдвинуться n раз и левый указатель может сдвинуться n раз. Это означает, что если логика для каждого окна равна O(1), алгоритмы скользящего окна работают за O(n), что **намного** быстрее.

> Вы можете подумать: внутри цикла for есть цикл while, разве временная сложность не O(n²)? Причина, по которой она всё ещё O(n), в том, что цикл while может выполниться суммарно не более n раз за весь алгоритм (`left` начинается с `0`, только увеличивается и никогда не превышает `n`). Если цикл while выполнится `n` раз на одной итерации цикла for, это значит, что он вообще не выполнится на всех остальных итерациях цикла for. Это то, что мы называем **амортизированным анализом (amortized analysis)** — хотя в худшем случае для одной итерации внутри цикла for стоимость равна O(n), в среднем она составляет O(1), если учитывать всё время работы алгоритма.

Теперь давайте рассмотрим несколько примеров скользящего окна.

> **Пример 1:** Дан массив положительных целых чисел `nums` и целое число `k`, найдите длину самого длинного подмассива, сумма которого меньше или равна `k`. Это та задача, о которой мы говорили выше. Теперь мы формально её решим.

Давайте используем целочисленную переменную `curr`, которая отслеживает сумму текущего окна. Так как задача хочет подмассивы, сумма которых меньше или равна `k`, мы хотим поддерживать `curr <= k`. Давайте рассмотрим пример, где `nums = [3, 1, 2, 7, 4, 2, 1, 1, 5]` и `k = 8`.

Окно начинается пустым, но мы можем расширить его до `[3, 1, 2]`, сохраняя ограничение. Однако после добавления `7` сумма окна становится слишком большой. Нам нужно сужать окно, пока сумма снова не станет меньше `8`, что не произойдёт, пока наше окно не будет выглядеть как `[7]`. Когда мы пытаемся добавить следующий элемент, наше окно снова становится слишком большим, и нам нужно удалить `7`, так что у нас остаётся `[4]`. Теперь мы можем расширять окно, пока оно не будет выглядеть как `[4, 2, 1, 1]`, но добавление следующего элемента делает сумму слишком большой. Мы удаляем элементы слева, пока ограничение снова не будет выполнено, что происходит при `[1, 1, 5]`. Самый длинный подмассив, который мы нашли, — `[4, 2, 1, 1]`, что означает, что ответ — `4`.

Когда мы добавляем элемент в окно, сдвигая правую границу, мы просто делаем `curr += value`. Когда мы удаляем элемент из окна, сдвигая левую границу, мы просто делаем `curr -= value`. Мы должны удалять элементы до тех пор, пока `curr > k`.

```python
def find_length(nums, k):
    # curr — текущая сумма окна
    left = curr = ans = 0
    for right in range(len(nums)):
        curr += nums[right]
        while curr > k:
            curr -= nums[left]
            left += 1
        ans = max(ans, right - left + 1)

    return ans
```

Для подмассива, начинающегося на `left` и заканчивающегося на `right`, длина равна `right - left + 1`. Как упоминалось ранее, этот алгоритм имеет временную сложность O(n), так как вся работа внутри цикла for является **амортизированной** O(1), где n — длина `nums`. Пространственная сложность константна, потому что мы используем только 3 целочисленные переменные.

> **Пример 2:** Вам дана двоичная строка `s` (строка, содержащая только `"0"` и `"1"`). Вы можете выбрать не более одного `"0"` и заменить его на `"1"`. Какова длина самой длинной подстроки, содержащей только `"1"`, которую можно получить?
>
> Например, для `s = "1101100111"` ответ — `5`. Если вы выполните замену по индексу `2`, строка станет `1111100111`.

Поскольку строка может содержать только `"1"` и `"0"`, другой способ взглянуть на эту задачу — "какова самая длинная подстрока, содержащая **не более одного** `"0"`?". Это позволяет легко решить задачу с помощью скользящего окна, где наше условие — `window.count("0") <= 1`. Мы можем использовать целочисленную переменную `curr`, которая отслеживает, сколько `"0"` у нас сейчас в окне.

```python
def find_length(s):
    # curr — текущее количество нулей в окне
    left = curr = ans = 0
    for right in range(len(s)):
        if s[right] == "0":
            curr += 1
        while curr > 1:
            if s[left] == "0":
                curr -= 1
            left += 1
        ans = max(ans, right - left + 1)

    return ans
```

Как и в предыдущем примере, эта задача выполняется за O(n) времени, где n — длина `s`, так как работа в каждой итерации цикла является амортизированной константой. Используются только несколько целочисленных переменных, что означает, что алгоритм использует O(1) памяти.

## Количество подмассивов

Если задача просит найти **количество подмассивов**, удовлетворяющих некоторому ограничению, мы всё ещё можем использовать скользящее окно, но нам нужно применить аккуратный математический трюк для подсчёта количества подмассивов.

Допустим, мы используем алгоритм скользящего окна, который мы изучили, и в данный момент у нас есть окно `(left, right)`. Сколько валидных окон **заканчиваются** на индексе `right`?

Это текущее окно `(left, right)`, затем `(left + 1, right)`, `(left + 2, right)` и так далее до `(right, right)` (только элемент на позиции `right`).

Вы можете зафиксировать правую границу и затем выбрать любое значение между `left` и `right` включительно для левой границы. Следовательно, количество валидных окон, **заканчивающихся** на индексе `right`, равно размеру окна, который мы знаем как `right - left + 1`.

> **Пример 3: 713. Subarray Product Less Than K.**
>
> Дан массив положительных целых чисел `nums` и целое число `k`, верните количество подмассивов, произведение всех элементов которых строго меньше `k`.
>
> Например, для входных данных `nums = [10, 5, 2, 6]`, `k = 100` ответ — `8`. Подмассивы с произведением меньше `k`:
>
> `[10]`, `[5]`, `[2]`, `[6]`, `[10, 5]`, `[5, 2]`, `[2, 6]`, `[5, 2, 6]`

Чтобы продемонстрировать свойство, которое мы только что изучили, давайте рассмотрим пример из описания. Когда мы достигаем индекса `2`, произведение становится слишком большим, поэтому нам нужно удалить самый левый элемент `10`. Теперь окно валидно и имеет длину `2`. Это означает, что существует `2` валидных подмассива, заканчивающихся здесь (`[2]` и `[5, 2]`).

Вспомните, что в предыдущих примерах мы обновляли ответ (самую длинную длину) после цикла while, когда окно должно быть валидным. Здесь мы можем вместо этого добавить текущий размер окна к нашему ответу. Ограничение, определяющее валидность окна, — произведение меньше `k`.

Дополнительно, обратите внимание, что если `k <= 1`, у нас никогда не может быть валидных окон, поэтому мы можем сразу вернуть `0`.

```python
class Solution:
    def numSubarrayProductLessThanK(self, nums: List[int], k: int) -> int:
        if k <= 1:
            return 0

        ans = left = 0
        curr = 1

        for right in range(len(nums)):
            curr *= nums[right]
            while curr >= k:
                curr //= nums[left]
                left += 1

            ans += right - left + 1

        return ans
```

Опять же, работа в каждой итерации цикла является амортизированной константой, поэтому этот алгоритм имеет время выполнения O(n), где n — длина `nums`, и O(1) памяти.

## Фиксированный размер окна

В примерах, которые мы рассмотрели выше, размер нашего окна был динамическим. Мы пытались расширить его вправо настолько, насколько могли, сохраняя ограничение, и удаляли элементы слева, когда ограничение нарушалось. Иногда задача будет задавать **фиксированную** длину `k`.

Эти задачи проще, потому что разница между любыми двумя соседними окнами — всего два элемента (мы добавляем один элемент справа и удаляем один элемент слева, чтобы сохранить длину).

Начните с построения первого окна (от индекса `0` до `k - 1`). Когда у нас есть окно размера `k`, если мы добавляем элемент на позиции `1`, нам нужно удалить элемент на позиции `i - k`. Например, `k = 2` и у вас в данный момент элементы на индексах `[0, 1]`. Теперь мы добавляем `2`: `[0, 1, 2]`. Чтобы сохранить размер окна `k = 2`, нам нужно удалить `2 - k = 0`: `[1, 2]`.

Вот псевдокод:

```
function fn(arr, k):
    curr = некоторые данные для отслеживания окна

    // построить первое окно
    for (int i = 0; i < k; i++)
        Сделать что-то с curr или другими переменными для построения первого окна

    ans = переменная для ответа, вероятно равная curr здесь, в зависимости от задачи
    for (int i = k; i < arr.length; i++)
        Добавить arr[i] в окно
        Удалить arr[i - k] из окна
        Обновить ans

    return ans
```

> **Пример 4:** Дан целочисленный массив `nums` и целое число `k`, найдите сумму подмассива с наибольшей суммой, длина которого равна `k`.

Как мы уже упоминали, мы можем построить окно длины `k` и затем скользить им по массиву. Добавляем и удаляем по одному элементу за раз, чтобы убедиться, что размер окна остаётся равным `k`. Если мы добавляем значение на позиции `i`, то нам нужно удалить значение на позиции `i - k`.

После построения первого окна мы инициализируем наш ответ значением `curr`, чтобы учесть сумму первого окна.

```python
def find_best_subarray(nums, k):
    curr = 0
    for i in range(k):
        curr += nums[i]

    ans = curr
    for i in range(k, len(nums)):
        curr += nums[i] - nums[i - k]
        ans = max(ans, curr)

    return ans
```

Общее количество итераций цикла for равно n, где n — длина `nums`, и работа в каждой итерации является константной, что даёт этому алгоритму временную сложность O(n) и O(1) памяти.
