# Еще примеры использования хеш-таблиц (More hashing examples)

Хеш-таблицы (hash maps) применяются практически повсеместно. Мы уже обсудили некоторые из наиболее распространенных паттернов, однако существует бесконечное множество способов интеграции хеш-таблиц в алгоритмы. Учитывая то, насколько важны хеш-таблицы, мы рассмотрим еще несколько примеров их использования в различных задачах. Крайне важно, чтобы вы уверенно владели хеш-таблицами, если хотите успешно проходить собеседования.

> **Пример 1: [49. Group Anagrams (Группировка анаграмм)](https://leetcode.com/problems/group-anagrams/)**
> 
> Дана строка или массив строк `strs`, сгруппируйте [анаграммы](https://leetcode.com/problems/group-anagrams/) вместе.
> 
> Например, для `strs = ["eat","tea","tan","ate","nat","bat"]` верните `[["bat"], ["nat","tan"], ["ate","eat","tea"]]`.

Как проверить, являются ли две строки анаграммами друг друга? Мы могли бы использовать две хеш-таблицы, подсчитать количество каждого символа в обеих строках, а затем сравнить хеш-таблицы на равенство. Однако реализовать это довольно громоздко, к тому же это не поможет нам сгруппировать строки вместе, если группа состоит более чем из двух строк. Для каждой группы нам необходим способ уникальной идентификации.

Самый чистый способ определить, являются ли две строки анаграммами друг друга — проверить, равны ли они после сортировки их символов. Кроме того, все строки в одной группе после сортировки станут абсолютно одинаковыми, поэтому мы можем использовать отсортированную версию строки в качестве ключа. Мы можем сопоставить эти ключи с самими группами в хеш-таблице, и тогда нашим ответом будут просто значения (values) этой хеш-таблицы.

По сути, у каждой группы есть свой «идентификатор» (отсортированная строка), и мы можем легко использовать его для группировки строк в хеш-таблице.

```python
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = defaultdict(list)
        for s in strs:
            key = "".join(sorted(s))
            groups[key].append(s)
            
        return list(groups.values())
```

> Примечание для Python: метод `dictionary.values()` возвращает не список (list), а специальный [объект представления (view object)](https://docs.python.org/3/library/stdtypes.html#dictionary-view-objects). Поэтому сначала нам нужно явно преобразовать его в список.

Обозначим $n$ как длину массива `strs`, а $m$ — как среднюю длину строки. Мы итерируемся по каждой строке и сортируем ее, что занимает $O(n \cdot m \cdot \log m)$ времени. Затем нам нужно проитерироваться по ключам хеш-таблицы. В худшем случае, когда совпадающих анаграмм нет, будет $n$ групп, что потребует $O(n)$ времени. Таким образом, общая временная сложность составляет $O(n \cdot m \cdot \log m)$ (дополнительное слагаемое $+n$ нивелируется). Пространственная сложность равна $O(n \cdot m)$, так как каждая строка будет помещена в массив внутри хеш-таблицы.

> Другой способ решения этой задачи — использовать в качестве ключа кортеж (tuple) длиной 26, представляющий количество вхождений каждого символа, вместо отсортированной строки. Формально это позволяет решить задачу за $O(n \cdot m)$, поскольку число 26 является константой, заданной условием задачи. Однако для тестов с короткими строками этот метод будет работать медленнее из-за константного множителя, который опускается в нотации «O» большое.
> 
> Кроме того, данный подход предполагает, что строки могут состоять только из 26 различных символов, что применимо в рамках этого условия, но является менее общим решением и хуже адаптируется под возможные усложнения задачи.

> **Пример 2: [2260. Minimum Consecutive Cards to Pick Up (Минимальное количество последовательных карт, которые нужно взять)](https://leetcode.com/problems/minimum-consecutive-cards-to-pick-up/)**
> 
> Дан целочисленный массив `cards`. Найдите длину кратчайшего подмассива, который содержит как минимум один дубликат. Если в массиве нет дубликатов, верните `-1`.

Мы могли бы решить эту задачу с помощью скользящего окна (sliding window), но давайте рассмотрим другой подход, в котором основной упор сделан на хеш-таблицу. Данный вопрос эквивалентен следующему: каково минимальное расстояние между любыми двумя одинаковыми элементами? Если мы пройдем по массиву и запишем в хеш-таблицу индексы для каждого элемента, то сможем проитерироваться по этим индексам для поиска кратчайшего расстояния. Например, для `cards = [1, 2, 6, 2, 1]` мы сопоставим `1: [0, 4]`, `2: [1, 3]` и `6: [2]`. Затем мы можем проитерироваться по значениям и увидеть, что минимальная разница достигается при выборе двоек (`2`).


```python
from collections import defaultdict

class Solution:
    def minimumCardPickup(self, cards: List[int]) -> int:
        dic = defaultdict(list)
        for i in range(len(cards)):
            dic[cards[i]].append(i)
            
        ans = float("inf")
        for key in dic:
            arr = dic[key]
            for i in range(len(arr) - 1):
                ans = min(ans, arr[i + 1] - arr[i] + 1)
                
        return ans if ans < float("inf") else -1
```

Временная сложность по-прежнему составляет $O(n)$, несмотря на наличие вложенного цикла в алгоритме. Это связано с тем, что внутренний цикл во вложенной конструкции суммарно выполняет не более $n$ итераций за все время работы, поскольку он итерируется по индексам элементов массива, где $n$ — длина входного массива.

Мы можем улучшить этот алгоритм, заметив, что нам не нужно хранить абсолютно все индексы, а достаточно помнить только самый последний встреченный индекс для каждого числа. Это снижает среднюю пространственную сложность. Текущий алгоритм всегда требует $O(n)$ памяти, но с этим улучшением пространственная сложность составит всего $O(n)$ в худшем случае — когда дубликаты отсутствуют.

```python
from collections import defaultdict

class Solution:
    def minimumCardPickup(self, cards: List[int]) -> int:
        dic = defaultdict(int)
        ans = float("inf")
        for i in range(len(cards)):
            if cards[i] in dic:
                ans = min(ans, i - dic[cards[i]] + 1)
                
            dic[cards[i]] = i
            
        return ans if ans < float("inf") else -1
```

Этот алгоритм также работает быстрее, так как мы экономим на одной итерации, хотя асимптотическая временная сложность обоих алгоритмов одинакова и составляет $O(n)$, где $n$ — длина входного массива.

> **Пример 3: [2342. Max Sum of a Pair With Equal Sum of Digits (Максимальная сумма пары с равной суммой цифр)](https://leetcode.com/problems/max-sum-of-a-pair-with-equal-sum-of-digits/)**
> 
> Дан массив целых чисел `nums`. Найдите максимальное значение суммы `nums[i] + nums[j]`, где `nums[i]` и `nums[j]` имеют одинаковую **сумму цифр** (сумму составляющих их отдельных цифр). Верните `-1`, если нет ни одной пары чисел с одинаковой суммой цифр.

Эта задача похожа на первый рассмотренный нами пример с группировкой анаграмм. В первом примере группы идентифицировались по их отсортированной строке. В этой задаче мы можем идентифицировать группу по сумме цифр числа. Мы итерируемся по массиву и группируем все числа с одинаковой суммой цифр в хеш-таблице. Затем мы можем пройтись по этой хеш-таблице и для каждой группы, содержащей как минимум 2 элемента, найти 2 максимальных элемента с помощью сортировки.
def_digit_sum это функция которая с помощью "modulo operator" берет последнюю цифру из числа и потом с помощью "//" отбрасывает ее от числа. Это стандартный математический способ. 

```python
from collections import defaultdict

class Solution:
    def maximumSum(self, nums: List[int]) -> int:
        def get_digit_sum(num):
            digit_sum = 0
            while num:
                digit_sum += num % 10
                num //= 10
                
            return digit_sum
            
        dic = defaultdict(list)
        for num in nums:
            digit_sum = get_digit_sum(num)
            dic[digit_sum].append(num)
            
        ans = -1
        for key in dic:
            if len(dic[key]) >= 2:
                dic[key].sort()
                ans = max(ans, dic[key][-1] + dic[key][-2])
                
        return ans
```

Этот алгоритм неэффективен из-за сортировки, которая в худшем случае может стоить $O(n \cdot \log n)$, если у каждого числа во входном массиве будет одинаковая сумма цифр, где $n$ — длина входного массива. Как и в предыдущей задаче, нам не обязательно хранить абсолютно все числа в группе. Мы можем улучшить временную и среднюю пространственную сложность, сохраняя только самое большое число, встреченное на данный момент для каждой конкретной суммы цифр.

```python
from collections import defaultdict

class Solution:
    def maximumSum(self, nums: List[int]) -> int:
        def get_digit_sum(num):
            digit_sum = 0
            while num:
                digit_sum += num % 10
                num //= 10
                
            return digit_sum
            
        dic = defaultdict(int)
        ans = -1
        for num in nums:
            digit_sum = get_digit_sum(num)
            if digit_sum in dic:
                ans = max(ans, num + dic[digit_sum])
            dic[digit_sum] = max(dic[digit_sum], num)
            
        return ans
```

Как и в прошлом примере, первый алгоритм всегда использует $O(n)$ памяти, поскольку мы сохраняем все элементы в значениях хеш-таблицы. С улучшением же в среднем случае будет использоваться гораздо меньше памяти, так как под каждым ключом хранится только одно целое число. Мы также экономим на одной итерации и сортировке в каждой итерации, что дает нам временную сложность $O(n)$, где $n$ — длина входного массива.

> **Пример 4: [2352. Equal Row and Column Pairs (Равные пары строк и столбцов)](https://leetcode.com/problems/equal-row-and-column-pairs/)**
> 
> Дана матрица `grid` размером `n x n`. Верните количество пар `(R, C)`, где `R` — строка, а `C` — столбец, при условии, что строка `R` и столбец `C` равны, если рассматривать их как одномерные массивы.

Как подсчитать количество равных пар? Предположим, у нас есть три строки, которые выглядят как `[1, 2, 3]`, и два столбца, которые тоже выглядят как `[1, 2, 3]`. Для каждой из трех строк найдутся два столбца для образования пары, то есть всего будет $3 \cdot 2 = 6$ пар. Мы можем использовать хеш-таблицу, чтобы подсчитать, сколько раз встречается каждая строка. Аналогично мы можем использовать вторую хеш-таблицу для столбцов. После этого мы можем проитерироваться по хеш-таблице строк и для каждой строки проверить, встречался ли такой же массив в качестве столбца. Если встречался, то к нашему ответу прибавляется произведение количества их появлений.

Проблема заключается в том, что массивы нельзя использовать в качестве ключей хеш-таблицы, так как они являются изменяемыми (mutable). Нам необходимо преобразовать строки и столбцы в хешируемый формат, например в строку (string) или кортеж (tuple). Наилучший выбор зависит от языка программирования, который вы используете.



```python
from collections import defaultdict

class Solution:
    def equalPairs(self, grid: List[List[int]]) -> int:
        def convert_to_key(arr):
            # Python — отличный язык для решения задач на собеседованиях!
            return tuple(arr)
            
        dic = defaultdict(int)
        for row in grid:
            dic[convert_to_key(row)] += 1
            
        dic2 = defaultdict(int)
        for col in range(len(grid[0])):
            current_col = []
            for row in range(len(grid)):
                current_col.append(grid[row][col])
                
            dic2[convert_to_key(current_col)] += 1
            
        ans = 0
        for key in dic:
            ans += dic[key] * dic2[key]
            
        return ans
```

Если размер матрицы составляет $n \times n$, временная сложность данного алгоритма равна $O(n^2)$ — здесь всего $n^2$ элементов, и каждый элемент изначально обходится дважды (один раз в строке, которую он занимает, и один раз в столбце). Заполнение хеш-таблиц и последующая итерация по ним будут занимать меньше времени и подчиняться этой сложности. Пространственная сложность составляет $O(n^2)$ — если все строки и столбцы уникальны, то каждая из двух хеш-таблиц вырастет до размера $n$, при этом каждый ключ будет иметь длину $n$.
