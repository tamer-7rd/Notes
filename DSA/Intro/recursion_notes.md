# Введение в рекурсию (Introduction to recursion)

## Основные понятия
Рекурсия — это метод решения проблем. В коде рекурсия реализуется с помощью функции, которая вызывает саму себя.

Противоположностью рекурсивного алгоритма является итеративный алгоритм. Существует раздел теории, который доказывает, что любой итеративный алгоритм может быть записан рекурсивно. В то время как итеративные алгоритмы используют циклы `for` и `while` для имитации повторения, рекурсивные алгоритмы используют вызовы функций для моделирования той же логики.

### Пример: вывод чисел
Допустим, мы хотим вывести числа от 1 до 10. Вот псевдокод для итеративного алгоритма:

```python
for i in range(1, 11):
    print(i)
```

Вот псевдокод для эквивалентного рекурсивного алгоритма:

```python
def fn(i):
    print(i)
    fn(i + 1)
    return

fn(1)
```

Каждый вызов `fn` сначала выводит `i` (которое начинается с 1), а затем снова вызывает `fn`, но увеличивая `i` (чтобы вывести следующее число).

> Первый вызов функции выводит `1`, затем вызывает `fn(2)`. В контексте вызова `fn(2)` выводится `2`, а затем вызывается `fn(3)` и так далее.

Однако этот код на самом деле неправильный. Видите проблему? Вызовы функций никогда не остановятся! Выполнение этого кода будет крутить бесконечный цикл вывода натуральных чисел (или пока компьютер не выдаст ошибку переполнения). Код никогда не дойдёт до оператора `return` на последней строке, потому что строка `fn(i + 1)` всегда срабатывает раньше него.

## Базовый случай (Base case)
Для того чтобы рекурсия остановилась, нам нужно то, что называется **базовым случаем** (base case). 
Базовые случаи — это условия (обычно в самом начале рекурсивных функций), которые завершают вызовы функции (делают `return`).

```python
def fn(i):
    if i > 10:
        return

    print(i)
    fn(i + 1)
    return

fn(1)
```

## Область Видимости (Scope)
Важно помнить, что каждый вызов функции имеет свою **локальную область видимости** (local scope). 
Поэтому, когда мы вызываем `fn(3)` в примере выше, в памяти одновременно существуют 3 "версии" переменной `i`:
- В первом вызове `i = 1`
- Во втором вызове `i = 2`
- В третьем вызове `i = 3`

Если бы мы добавили `i += 1` внутри вызова `fn(3)`, значение `i` стало бы равным `4` **только** внутри вызова `fn(3)`. Две другие «версии» переменной `i` остались бы нетронутыми, потому что они находятся в разных областях видимости (scopes). Соответственно ход выполнения строк кода запоминается для каждой функции в стеке отдельно, и код продолжает исполняться по порядку.

## Разбиение проблем на части (Breaking problems down)
Вывод чисел таким образом довольно бессмысленен — для этого гораздо проще использовать цикл `for`. 
Рекурсия начинает сиять настоящими красками, когда вы используете её для разбиения проблемы на **"подзадачи"**, решения которых затем могут быть объединены для создания решения исходной проблемы.

### Числа Фибоначчи
Давайте посмотрим на числа Фибоначчи. Числа Фибоначчи — это последовательность чисел, начинающаяся с `0, 1`. Затем каждое последующее число определяется как сумма двух предыдущих: `0, 1, 1, 2, 3, 5, 8...`

Более формально мы имеем уравнение:

> $F_n = F_{n-1} + F_{n-2}$

Это называется **рекуррентным соотношением** (recurrence relation) — уравнением, которое связывает элементы последовательности вместе.

Давайте напишем функцию `F(n)`, которая возвращает $n$-ное число Фибоначчи (с индексом от 0). Не забывайте, что любой рекурсивной функции нужны базовые случаи. В случае Фибоначчи базовые случаи определяются явно по условию: `F(0) = 0` и `F(1) = 1`.

```python
def F(n):
    # Базовые случаи
    if n <= 1:
        return n
    
    # Рекуррентное соотношение
    oneBack = F(n - 1)
    twoBack = F(n - 2)
    return oneBack + twoBack
```

Допустим, мы хотим найти `F(3)`. При вызове `F(3)` мы бы увидели следующий поток выполнения (каждый уровень отступа представляет новую область видимости вызова функции):

```
oneBack = F(2)
    oneBack = F(1)
        F(1) = 1
    twoBack = F(0)
        F(0) = 0
    F(2) = oneBack + twoBack = 1    (1 + 0)
twoBack = F(1)
    F(1) = 1
F(3) = oneBack + twoBack = 2        (1 + 1)
```

Как видите, мы взяли исходную проблему `F(3)` и разбили её на две меньшие подзадачи — `F(2)` и `F(1)`. Объединив рекуррентное соотношение и базовые случаи, мы смогли решить эти подзадачи и использовать их решения для ответа на наш изначальный вопрос.

Это самое распространенное применение рекурсии — ваша рекурсивная функция **возвращает ответ на проблему, которую вы пытаетесь решить для данного ввода**. В этом примере проблема звучала как "Каким является $n$-ное число Фибоначчи?". Располагая базовыми случаями и рекуррентным соотношением мы легко реализовали данную функцию.

Следуя этой идее, решение подзадач становится тривиальным: если бы мы хотели найти 100-е число Фибоначчи, мы по определению знаем, что оно является суммой 99-го и 98-го чисел Фибоначчи. При вызове `F(100)`, вызовы подзадач `F(99)` и `F(98)` предоставят нам необходимые числа.

## Порядок выполнения
Важная вещь, которую нужно понимать о рекурсии, — это порядок (очередность) в котором выполняется код. С итеративной программой всё просто: выполнение начинается сверху и идёт построчно вниз. В рекурсии же логика может наслаиваться. 
Давайте снова выведем наши числа, но теперь только от 1 до 3. Давайте также добавим еще один оператор вывода (`print`) и пронумеруем строки кода:

```python
def fn(i):
1.  if i > 3:
2.      return
3.  
4.  print(i)
5.  fn(i + 1)
6.  print(f"End of call where i = {i}")
7.  return

fn(1)
```

Если вы запустите этот код, вы увидите следующий вывод:
```
// 1
// 2
// 3
// End of call where i = 3
// End of call where i = 2
// End of call where i = 1
```

Как видите, строка текста (`строка 6`), выполняется в **обратном порядке**. 
1. Исходный вызов `fn(1)` сначала выводит `1`, затем вызывает `fn(2)`. 
2. `fn(2)` выводит `2`, затем вызывает `fn(3)`. 
3. `fn(3)` выводит `3`, затем вызывает `fn(4)`. 
4. **Теперь важный момент (как рекурсия "движется" обратно вверх):** в вызове `fn(4)` мы попадаем на базовый случай, что приводит к возврату (`return`). 
5. Теперь мы возвращаемся назад в функцию, где `i = 3`. **Здесь строка 5 (`fn(i+1)`) завершает свое выполнение**, поэтому мы переходим на следующую **строку 6**, которая выводит `"End of call where i = 3"`. Отработав, она переходит к строке 7 (`return`).
6. Теперь мы снова оказываемся "наверх" по цепи, внутри функции где `i = 2`. Здесь также **строка 5 завершила свое выполнение**, мы идем на **строку 6** и выводим `"End of call where i = 2"`. 
7. Это поведение повторяется, пока самый первый вызов `fn(1)` не выполнит свой `return` и не завершит программу.

Каждый вызов функции "существует" в памяти до тех пор, пока он не сделает возврат (`return`). Когда мы переходим к новому вызову функции, старый вызов становится "на паузу" в ожидании, пока не отработает новый текущий вызов. Порядок возвращения каскадный.

## Зачем мы вообще изучаем Фибоначчи?

Это очень правильный и честный вопрос, потому что в реальной работе числа Фибоначчи сами по себе почти никогда не нужны. Фибоначчи — это своего рода тренировочный манекен. Как груша в боксе — никто не дерётся с грушей на улице, но на ней ставят удар. 

В данном случае **вы учите не числа Фибоначчи, вы учитесь алгоритмическому мышлению**.

### Что реально здесь тренируется?
Когда вы смотрите на уравнение $F(n) = F(n-1) + F(n-2)$, вы учитесь видеть проблему под другим углом: **большую задачу можно выразить через более маленькие версии самой себя**. 
Это фундаментальный принцип для 80% сложных алгоритмов.

### Где это применяется на практике?

**1. Динамическое программирование (Dynamic Programming)**
Это половина всех задач на платформе LeetCode и база для собеседований в Google, Meta, Amazon.
Самые частые задачи звучат так:
- Найти минимальную стоимость (minimum cost)
- Найти максимальную прибыль (maximum profit)
- Найти кратчайший путь (shortest path)
- Посчитать количество способов сделать что-либо
- Найти оптимальное решение

Все они строятся по одному шаблону: 
> `Ответ(n) = лучший вариант из предыдущих состояний + новый выбор`

Например, сколько есть способов подняться по лестнице, если можно шагать на 1 или на 2 ступеньки? 
`ways(n) = ways(n-1) + ways(n-2)`. Это та же самая логика Фибоначчи!

**2. Разделяй и властвуй (Divide & Conquer)**
Популярные алгоритмы вроде сортировки слиянием (Merge Sort), быстрой сортировки (Quick Sort) и бинарного поиска (Binary Search) работают по идее: *реши маленькие части $\rightarrow$ объедини их в общий результат*. Это та же философия, что и в базовой рекурсии.

**3. Понимание рекурсивных структур**
Без нормального понимания рекурсии невозможно освоить:
- Деревья (Trees) и графы (Graphs)
- Алгоритм поиска в глубину (DFS)
- Поиск с возвратом (Backtracking)
- Обход файловой системы (ведь папка содержит папки, которые содержат папки...)
- Процесс сверки в React (React reconciliation) — да, там тоже активно используется рекурсия.

**4. Оптимизация и понимание медленного алгоритма**
Числа Фибоначчи показывают нам важную вещь: наивный, красивый на вид код способен работать ужасно медленно. 
Код `F(n-1) + F(n-2)` заставляет компьютер повторять одни и те же вычисления множество раз. Это закладывает понимание того, откуда берутся **мемоизация (memoization)**, **кэширование (caching)**, **динамическое программирование** и оптимизация ресурсов времени. Это и есть инженерное мышление.

### Самая важная правда

Senior-разработчик, глядя на новую сложную задачу, практически мгновенно задает себе вопрос: 
**"Могу ли я выразить это через меньшую версию этой же задачи?"**

Если ответ "да" — задача почти решена. Пример с числами Фибоначчи — это первый раз, когда ваш мозг учится этому специфическому рефлексу. Индустрия редко требует писать сам алгоритм Фибоначчи, но она постоянно требует решать задачи, где "лучшее решение сейчас" базируется на "лучшем решении вчера + новый выбор".

Если этот паттерн не встроен в мышление — алгоритмы выглядят как хаос из независимых тем. Если встроен — задачи начинают повторяться. В какой-то момент алгоритмы действительно перестают казаться набором разных задач и превращаются в 5–6 повторяющихся идей. И числа Фибоначчи — это самая первая дверь в эту комнату.
