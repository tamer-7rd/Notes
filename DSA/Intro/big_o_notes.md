# Введение в Big O и основы анализа алгоритмов

Детальный конспект на основе предоставленных материалов, охватывающий концепции временной и пространственной сложности, правила вычисления Big O и примеры.

---

## Что такое алгоритм?
В контексте программирования и платформ вроде LeetCode, **алгоритм** можно представить как «пошаговый рецепт», которому должен следовать компьютер для решения задачи.
- Алгоритм принимает **входные данные (input)** и генерирует **результат (output)**.
- **Основные требования к алгоритмам:**
  1. **Детерминированность:** При одинаковых входных данных алгоритм должен ВСЕГДА выдавать абсолютно одинаковый результат (без доли случайности).
  2. **Обязательная корректность:** Алгоритм должен работать правильно для *любых* произвольных и допустимых входных данных (например, если ожидается массив положительных чисел, алгоритм не должен ломаться и обязан учесть все пограничные случаи в рамках таких массивов).

---

## Что такое Big O?
Нотация **Big O (О-большое)** используется для описания **«вычислительной сложности» (computational complexity)** алгоритма. Эта сложность делится на два основных направления:

1. **Временная сложность (Time complexity):** По мере роста размера входных данных, насколько дольше будет выполняться алгоритм?
2. **Пространственная сложность (Space complexity):** По мере роста размера входных данных, насколько больше оперативной памяти потребует алгоритм?

*(И хотя зачастую временной сложности придают большее значение, на технических собеседованиях крайне важно понимать и учитывать их обе).*

### Как работают переменные в сложности
Сложность описывается математической функцией (формулой).
- В ней используются переменные, которые отражают изменяющиеся параметры входных данных, напрямую влияющие на работу алгоритма.
- Самой популярной и общепринятой переменной является **$\mathbf{n}$** (чаще всего она означает длину входного массива или строки). Использовать $n$ — это стандарт, хотя технически можно было бы взять любую букву или даже эмодзи.
- Примеры оформления сложности: **$O(n)$**, **$O(n^2)$**, **$O(2^n)$**, **$O(\log n)$**, **$O(n \cdot m)$**. 

Смысл сложности в том, чтобы понять, **как ведет себя алгоритм при изменении (росте) входных данных**.

---

## Правила подсчета и вычисления сложности

Основная суть: временная сложность не означает точное количество операций. Если массив равен 10 элементам, а выполняется 12 операций, мы всё равно смотрим именно на масштаб, на то, как количество операций зависит от размера $n$.

1. **Игнорирование констант (постоянных множителей)**
   - В вычислении Big O мы отбрасываем константы.
   - Пример: $O(9999999n) = O(8n) = O(n) = O(\frac{n}{500})$.
   - **Почему?** Потому что мы смотрим на скорость роста функций. И $n$ операций, и $5n$ операций при увеличении в 2 раза увеличат количество итераций ровно в 2 раза (рост линейный). Поэтому оба алгоритма считаются как $O(n)$.

2. **Оценка при $n$, стремящемся к бесконечности**
   - При подсчете сложности мы принимаем, что переменные стремятся к бесконечности. Как только появляется сложение или вычитание, **мы игнорируем все слагаемые, кроме одного — самого «мощного» (самого быстрорастущего).**
   - Пример: $O(2^n + n^2 - 500n)$. При $n \to \infty$, слагаемое $2^n$ вырастает до таких масштабов, что $n^2$ и $-500n$ становятся практически нулями на его фоне. Поэтому:  $O(2^n + n^2 - 500n) = \mathbf{O(2^n)}$.

3. **Константная сложность $O(1)$**
   - Наилучшая возможная сложность называется **$O(1)$** («константное время» или «константная память»).
   - Это значит, что алгоритм **ВСЕГДА** использует строго одинаковое количество ресурсов (времени или памяти) *независимо от размера входных данных*.
   - Важно понимать: $O(1)$ не всегда означает, что алгоритм молниеносен. Алгоритм может стабильно выполнять $5,000,000$ операций и это будет $O(1)$, если такое количество операций не зависит от размера ввода $n$.

### Три сценария сложности:
Обычно рассматриваются три сценария работы алгоритма:
- **Best case (Лучший случай)**.
- **Average case (Средний случай)**.
- **Worst case (Худший случай)**.

Часто во всех 3-х случаях сложность одинакова, но иногда отличается. Если вам нужно выбрать или назвать всего одну сложность, **всегда выбирайте Худший сценарий (Worst case)**, так как он наиболее честный и безопасный для представления алгоритма.

## Анализ временной сложности (Time Complexity)

Давайте разберем основные примеры (основываясь на псевдо-коде).

**1. Линейное время $O(n)$**
```java
// Дан целочисленный массив "arr" длиной n
for (int num: arr) {
    print(num)
}
```
**Сложность: $O(n)$.** В каждой итерации цикла распечатка стоит $O(1)$. Цикл выполняется $n$ раз, что дает суммарно $O(1 \cdot n) = O(n)$.

**2. Игнорирование константы во вложенном цикле**
```java
// Дан массив "arr" длиной n
for (int num: arr) {
    for (int i = 0; i < 500000; i++) {
        print(num)
    }
}
```
**Сложность: $O(n)$.** Внутренний цикл всегда выполняется ровно $500,000$ раз, без зависимости от чего-либо. Это $O(1)$ для внутреннего блока. Внешний цикл зависит от массива длины $n$. Суммарно: $O(500000) = O(1)$, следовательно, $500000 \cdot n \to \mathbf{O(n)}$.

**3. Последовательные независимые циклы**
```java
// "arr" длины n, "arr2" длины m
for (int num: arr) { print(num) }
for (int num: arr) { print(num) }
for (int num: arr2) { print(num) }
```
**Сложность: $O(n + m)$.** Первые два цикла стоят по $O(n)$. Третий $O(m)$. Сумма: $O(2n + m)$, что по правилам приводится к $\mathbf{O(n + m)}$.

**4. Квадратичное время $O(n^2)$ (вложенные циклы)**
```java
// Вложенные циклы
for (int num: arr) {
    for (int num2: arr) {
        print(num * num2)
    }
}
```
**Сложность: $O(n^2)$.** Внешний цикл работает $n$ раз. Для *каждого* внешнего шага внутренний тоже работает $n$ раз. Умножаем $n \cdot n = \mathbf{O(n^2)}$.

**5. Вложенный цикл, зависящий от текущего шага внешнего**
```java
for (int i = 0; i < arr.length; i++) {
    for (int j = i; j < arr.length; j++) {
        print(arr[i] + arr[j])
    }
}
```
**Сложность: $O(n^2)$.** Внутренний цикл зависит от переменной `i`. При первой итерации он выполнится $n$ раз, затем $n-1$ раз, затем $n-2$ и т.д. В итоге это математическая прогрессия: $1 + 2 + 3 + ... + n = \frac{n(n+1)}{2} = \frac{n^2 + n}{2}$. В нотации Big O мы игнорируем константу (деление на 2) и отбрасываем слабое слагаемое $n$. Остается $\mathbf{O(n^2)}$.

## Логарифмическое время $O(\log n)$
Логарифм — обратная операция к возведению в степень. В контексте логарифмического времени — оно **экстремально быстрое**. Алгоритмы, имеющие сложность порядка $O(n \cdot \log n)$ или просто $O(\log n)$ считаются очень производительными.
- Обычно для Big O подразумевается логарифм с основанием 2 ($\log_2 n$). Но для нотации основание не перечисляется, так как разные основания отличаются лишь константным коэффициентом.
- Наличие $O(\log n)$ означает, что на каждом шаге объем обрабатываемой информации (размер входного массива) **сокращается на какой-то процент (обычно в два раза)**.
- **Классический пример — Бинарный поиск (Binary Search)**. Сначала рассматриваются все $n$ элементов, на втором шаге $n / 2$, потом $n / 4$ и так далее (сокращение области поиска на 50% каждый раз). В итоге получаем логарифмическую временную сложность $O(\log n)$.

## Анализ пространственной сложности (Space Complexity)

Когда инициализируются переменные — массивы, строки и т.д., алгоритм резервирует память.
**Главные правила:**
- Мы **никогда не считаем память, уже занятую самими входными данными (input)**. Кстати, менять входной массив ради решения — очень плохая практика.
- Мы **обычно не учитываем память, формирующую конечный ответ (output)** алгоритма, если только нас об этом специально не попросили (на собеседовании).
- Учитывается только *вспомогательная/дополнительная* память, аллоцированная во время вычислений.

**1. Константная память $O(1)$**
```java
// Дан массив "arr" длины n
for (int num: arr) {
    print(num)
}
```
**Сложность: $O(1)$.** Единственная память, которая была здесь выделена вручную — это целочисленная переменная `num`. Она константна по отношению к размеру массива (размер одной переменной не будет расти при увеличении размера массива).

**2. Линейная память $O(n)$**
```java
Array doubledNums = int[]
for (int num: arr) {
    doubledNums.add(num * 2)
}
```
**Сложность: $O(n)$.** В конце работы массив `doubledNums` будет содержать ровно $n$ целых чисел. Под этот массив была выделена память, прямо зависящая от длины входных данных.

**3. Линейная память с игнорированием константы**
```java
Array nums = int[]
int oneHundredth = n / 100

for (int i = 0; i < oneHundredth; i++) {
    nums.add(arr[i])
}
```
**Сложность: $O(n)$.** Внутренний массив содержит $1\%$ чисел из оригинального массива $arr$. Сложность составляет $O(\frac{n}{100})$, но так как мы отбрасываем константы (деление на 100), получаем $\mathbf{O(n)}$.

**4. Полиномиальная (матричная) память $O(n \cdot m)$**
```java
// Даны массивы arr(длина n) и arr2(длина m)
Array grid = int[n][m]

for (int i = 0; i < arr.length; i++) {
    for (int j = 0; j < arr2.length; j++) {
        grid[i][j] = arr[i] * arr2[j]
    }
}
```
**Сложность: $O(n \cdot m)$.** Алгоритм создает двумерную сетку (`grid`), содержащую как раз $n$ рядов по $m$ столбцов. Выделенная память напрямую зависит от перемножения величин $n$ и $m$.
