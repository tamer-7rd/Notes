# TypeScript, Babel и SWC

## ⚡ Главный вопрос: Я сам это настраиваю?

**Короткий ответ:** Зависит от инструмента!

| Инструмент | Ты устанавливаешь? | Ты настраиваешь? | Где он? |
|------------|-------------------|------------------|---------|
| **TypeScript** | ✅ Да | ✅ Да (создаёшь `tsconfig.json`) | Видно в `package.json` |
| **Babel** | ❌ Нет | ❌ Нет | Спрятан внутри фреймворка |
| **SWC** | ❌ Нет | ❌ Нет | Спрятан внутри фреймворка |

### Почему TypeScript видно, а Babel/SWC нет?

**TypeScript** — ты видишь его в `package.json`, потому что он нужен для **проверки типов** в редакторе (VS Code подсказки).

**Babel/SWC** — спрятаны внутри фреймворка (Next.js, Vite). Ты их вообще не видишь. Они работают только при сборке (`npm run build`) или запуске (`npm run dev`).

**Пример Next.js:**
```json
{
  "dependencies": {
    "next": "^14.0.0"  // Внутри Next.js уже есть SWC
  },
  "devDependencies": {
    "typescript": "^5.0.0"  // Только TypeScript для проверки типов
  }
}
```
👆 Babel/SWC нет в списке — они внутри Next.js!

👉 **Подробнее об этом читай в разделе ["Сам настраиваешь или уже встроено?"](#️-важно-сам-настраиваешь-или-уже-встроено)**

## Уровень 1: Зачем это нужно?

Представь, что ты пишешь письмо другу, но:
- Ты хочешь использовать современные слова и сленг
- Но твой друг понимает только старый язык
- И ещё ты хочешь проверить грамматику перед отправкой

**TypeScript, Babel и SWC** — это инструменты, которые помогают с этими проблемами.

## TypeScript — проверка типов

### Что это?
**TypeScript** — это расширенная версия JavaScript с дополнительной системой проверки.

**Представь:**
- **JavaScript** — это обычный текст, который ты пишешь без проверки
- **TypeScript** — это тот же текст, но с проверкой грамматики и орфографии ДО отправки

**Что добавляет TypeScript:**
- **Типы данных** — ты указываешь, что переменная должна быть числом, строкой и т.д.
- **Проверка ошибок** — TypeScript находит ошибки ДО того, как код запустится
- **Подсказки** — редактор кода подсказывает, что можно написать

**Аналогия:** Как Microsoft Word с проверкой орфографии:
- Ты пишешь текст (код)
- Word подчёркивает ошибки красным (TypeScript показывает ошибки)
- Ты исправляешь ошибки ДО отправки (ДО запуска кода)

**Простыми словами:** TypeScript — это JavaScript с проверкой типов, который помогает найти ошибки ещё до запуска программы.

### Простой пример

**JavaScript (без проверки):**
```javascript
function add(a, b) {
    return a + b;
}

add(5, "10");  // Результат: "510" — WTF?! 😱
```

**TypeScript (с проверкой):**
```typescript
function add(a: number, b: number): number {
    return a + b;
}

add(5, "10");  // ❌ ОШИБКА: "10" это не число!
```

### Что делает TypeScript-компилятор (tsc)?

```
Твой код (app.ts)
      ↓
TypeScript Compiler (tsc)
      ↓
1. Проверяет типы (number, string, etc.)
2. Если ошибки — останавливается и показывает их
3. Если всё ОК — удаляет все типы
      ↓
Чистый JavaScript (app.js)
```

**Важно:** TypeScript НЕ выполняет код! Он только:
1. Проверяет типы
2. Превращает TypeScript в JavaScript

### Практический пример

**Файл: app.ts**
```typescript
interface User {
    name: string;
    age: number;
}

function greet(user: User): string {
    return `Hello, ${user.name}!`;
}

const user = { name: "Tamerlan", age: 25 };
greet(user);
```

**Компиляция:**
```bash
tsc app.ts
```

**Результат: app.js**
```javascript
function greet(user) {
    return `Hello, ${user.name}!`;
}

const user = { name: "Tamerlan", age: 25 };
greet(user);
```

Видишь? Все типы (`interface`, `: User`, `: string`) исчезли!

## Babel — переводчик современного JS в старый

### Что это?
**Babel** — это программа (инструмент), которая читает твой JavaScript код и переписывает его.

Представь Babel как **переводчик между версиями JavaScript**:
- Ты пишешь на современном JavaScript (ES2023)
- Babel переводит это в старый JavaScript (ES5)
- Старый JavaScript понимают даже древние браузеры (IE11)

**Простыми словами:** Babel берёт твой крутой современный код и делает его понятным для старых браузеров.

**Аналогия:** Как если бы ты написал текст с современным сленгом, а Babel переписал его классическим языком, который поймут даже бабушки и дедушки.

### Зачем это нужно?
Ты хочешь использовать новые фичи JavaScript (ES2023), но старые браузеры их не понимают.

**Проблема:**
- Ты пишешь: `const name = user?.profile?.name ?? "Guest"`
- Старый браузер: "WTF?! Что это за `?.` и `??`?" 😱

**Решение:**
- Babel переписывает это в старый синтаксис
- Старый браузер: "А, понятно! Это просто проверки!" ✅

### Что делает Babel?

```
Современный JavaScript (ES2023)
      ↓
      BABEL
      ↓
Старый JavaScript (ES5), который понимают все браузеры
```

### Пример

**Твой код (современный):**
```javascript
// Стрелочная функция (ES6)
const greet = (name) => `Hello, ${name}!`;

// Optional chaining (ES2020)
const userName = user?.profile?.name;

// Nullish coalescing (ES2020)
const displayName = userName ?? "Guest";
```

**После Babel (старый JS):**
```javascript
// Обычная функция
var greet = function(name) {
    return "Hello, " + name + "!";
};

// Проверки вручную
var userName = user && user.profile && user.profile.name;

// Тернарный оператор
var displayName = userName !== null && userName !== undefined ? userName : "Guest";
```

### Как работает Babel?

1. **Парсинг** — читает твой код и превращает в дерево (AST)
2. **Трансформация** — меняет новые конструкции на старые
3. **Генерация** — создаёт новый код

```
const add = (a, b) => a + b;
      ↓ Парсинг
AST (дерево)
      ↓ Трансформация
Новое AST (со старым синтаксисом)
      ↓ Генерация
var add = function(a, b) { return a + b; };
```

## SWC — быстрая альтернатива Babel

### Что это?
**SWC** (Speedy Web Compiler) — это тоже программа-переводчик JavaScript, как Babel.

**Главное отличие:**
- **Babel** написан на JavaScript
- **SWC** написан на Rust (очень быстрый язык программирования)

**Что делает SWC:**
- То же самое, что Babel — переводит современный JS в старый
- Но делает это **в 20-70 раз быстрее!** 🚀

**Аналогия:** Представь двух переводчиков:
- Babel — опытный переводчик, который работает вручную (медленнее, но надёжно)
- SWC — тот же переводчик, но с суперкомпьютером (делает то же самое, но молниеносно)

**Простыми словами:** SWC — это более быстрая версия Babel. Результат одинаковый, но скорость работы намного выше.

### Сравнение

| Инструмент | Язык | Скорость | Использование |
|------------|------|----------|---------------|
| **Babel** | JavaScript | Медленнее | Старые проекты, много плагинов |
| **SWC** | Rust | Очень быстро | Новые проекты (Next.js 12+) |

### Пример использования SWC

```bash
# Установка
npm install @swc/core

# Компиляция
npx swc src/app.js -o dist/app.js
```

**Тот же результат, что Babel, но быстрее!**

### Короткий ответ:

### Вариант 1: Фреймворк всё делает за тебя (Next.js, Vite, Create React App)

**Ты НЕ настраиваешь эти инструменты вручную!** Они уже встроены и работают "под капотом".

#### Пример: Next.js

```bash
# Создаёшь проект
npx create-next-app@latest my-app

# Пишешь код на TypeScript
# app/page.tsx
export default function Home() {
    return <h1>Hello!</h1>
}

# Запускаешь
npm run dev
```

**Что происходит под капотом:**
```
Next.js автоматически:
├─ Использует TypeScript компилятор (встроен!)
├─ Использует SWC для транспиляции (встроен!)
├─ Превращает твой код в JavaScript
└─ Ты даже не видишь этих инструментов!
```

**Ты просто пишешь код, а Next.js сам:**
- Компилирует TypeScript
- Транспилирует современный JS
- Собирает bundle
- Оптимизирует

**Конфигурация:** Минимальная или вообще не нужна! ✅

---

#### Пример: Vite

```bash
# Создаёшь проект
npm create vite@latest my-app -- --template react-ts

# Пишешь код
# src/App.tsx
export default function App() {
    return <h1>Hello!</h1>
}

# Запускаешь
npm run dev
```

**Что происходит под капотом:**
```
Vite автоматически:
├─ Использует esbuild для TypeScript (встроен!)
├─ Превращает TSX → JSX → JavaScript
├─ Отдаёт код браузеру
└─ Всё работает без настройки!
```

**Конфигурация:** Почти не нужна! ✅

### Вариант 2: Настраиваешь сам (старые проекты, custom setup)

**Ты САМ устанавливаешь и настраиваешь каждый инструмент.**

#### Пример: Проект с нуля

```bash
# Создаёшь папку
mkdir my-project
cd my-project
npm init -y

# Устанавливаешь TypeScript ВРУЧНУЮ
npm install -D typescript

# Создаёшь конфигурацию tsconfig.json ВРУЧНУЮ
npx tsc --init

# Устанавливаешь Babel ВРУЧНУЮ
npm install -D @babel/core @babel/cli @babel/preset-env

# Создаёшь конфигурацию .babelrc ВРУЧНУЮ
echo '{"presets": ["@babel/preset-env"]}' > .babelrc

# Настраиваешь скрипты в package.json ВРУЧНУЮ
```

**Это сложно и долго!** ⚠️

| Аспект | Фреймворк (Next.js, Vite) | Вручную |

## Как это всё работает вместе?

### Типичный современный проект

```
Твой код (TypeScript + современный JS)
      ↓
TypeScript Compiler (tsc)
  - Проверяет типы
  - Удаляет типы
      ↓
Современный JavaScript
      ↓
Babel или SWC
  - Превращает в старый JS
  - Добавляет полифиллы
      ↓
JavaScript, который работает везде
```

### Пример с Next.js

**Ты пишешь:**
```typescript
// app/page.tsx
interface Props {
    title: string;
}

export default function Home({ title }: Props) {
    return <h1>{title}</h1>;
}
```

**Что происходит при `npm run build`:**

1. **TypeScript** проверяет типы
2. **SWC** (в Next.js 12+):
   - Удаляет типы
   - Превращает JSX в JavaScript
   - Транспилирует современный синтаксис
3. Получается код, который работает в браузерах

```json
{
```

### С SWC

**package.json:**
```json
{
  "scripts": {
    "build": "swc src -d dist"
  },
  "devDependencies": {
    "@swc/core": "^1.3.0",
```

**.swcrc:**
```json
{
  "jsc": {
    "parser": {
      "syntax": "ecmascript"
    },
    "target": "es5"
  }
}
```

## Главные выводы

### TypeScript
- **Цель:** Проверить типы и найти ошибки ДО запуска
- **Результат:** Чистый JavaScript без типов
- **Когда:** Build-time (при сборке)

### Babel
- **Цель:** Превратить современный JS в старый
- **Результат:** JS, который работает в старых браузерах
- **Когда:** Build-time (при сборке)

### SWC
- **Цель:** То же, что Babel, но быстрее
- **Результат:** То же, что Babel
- **Когда:** Build-time (при сборке)

**Все эти инструменты работают ДО запуска кода** — это Build-time инструменты!
