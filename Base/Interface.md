**Конспект: Понятие, типы и назначение программных интерфейсов**

### 1. Что такое Интерфейс в программировании?

**Интерфейс** — это, по сути, **контракт (договор) или спецификация**, определяющая правила взаимодействия между различными частями программы, разными программами или человеком и программой. Он устанавливает, **что** объект или компонент умеет делать (какие методы доступны), но не описывает, **как** он это делает, что позволяет скрыть внутреннюю сложность реализации. Интерфейс выступает как шаблон или правило.

Концепция интерфейсов является **фундаментом программирования по контракту** (Design by Contract, DbC), поскольку они устанавливают взаимные обязательства между элементами программной системы.

### 2. Основные типы интерфейсов

Интерфейсы используются для обеспечения взаимодействия на разных уровнях:

1.  **Интерфейс пользователя (UI, User Interface):** Средства, обеспечивающие взаимодействие человека с программой. Примеры: кнопки, меню, окна.
2.  **Программный интерфейс приложения (API, Application Programming Interface):** Набор правил и функций, который позволяет программам общаться и обмениваться данными. Например, использование Google Maps API вашим приложением.
3.  **Интерфейс в ООП (Объектно-ориентированное программирование):** Строго формализованный элемент языка, который определяет отношение с объектами, объединенными общим поведением.

### 3. Для чего нужны интерфейсы?

Использование интерфейсов преследует несколько ключевых целей в разработке:

*   **Абстракция и сокрытие деталей:** Интерфейс позволяет работать с функциональностью, не зная ее внутренней реализации (подобно тому, как вы пользуетесь выключателем, не зная устройства электричества).
*   **Полиморфизм:** Это возможность работать с разными объектами единообразно, если они реализуют один и тот же интерфейс. Интерфейсы являются одним из вариантов обеспечения полиморфизма в объектных языках.
*   **Модульность и расширяемость:** Они упрощают создание и интеграцию новых компонентов, так как эти компоненты должны лишь соответствовать определенному контракту (интерфейсу), что позволяет разбить программную систему на модули без взаимной зависимости кода.
*   **Типизация:** Интерфейс может использоваться как тип данных для переменных и параметров, так как он определяет внешнее поведение объектов. Переменная типа «интерфейс» может содержать экземпляр любого класса, который его реализует.

### 4. Интерфейс как Контракт в ООП

**Интерфейс в ООП** описывает **имя** и **методы**. В описании интерфейса определяются только имена и сигнатуры методов, без их кода.

Класс, который **реализует** интерфейс, обязуется предоставить реализацию **всех** методов, описанных в этом интерфейсе.

**Аналогия:** Интерфейс — это как инструкция для сборщика мебели, которая говорит: «Должны быть ножки, столешница, ящик». Класс — это конкретный стол, который реализует: «Ножки из дуба, столешница из стекла».

#### Что может и не может содержать чистый интерфейс

*   **Может содержать:** Названия функций (без тел). Некоторые языки допускают функции-утилиты, эталонные (рабочие) реализации или статические (неизменяемые) данные.
*   **Не может содержать:** Любые нестатические данные (кроме технических), конструктор (кроме технической инициализации), приватные или незаконченные функции.

### 5. Реализация Интерфейсов в разных языках

Реализация зависит от объектной подсистемы языка, в частности, от поддержки множественного наследования. Введение интерфейсов во многих языках является компромиссом, позволяющим получить преимущества множественного наследования без связанных с ним проблем (например, «проблемы ромбовидного наследования»).

```
+----------------------+---------------------------+------------------------------------------------+
| Язык                 | Конструкция               | Примечание                                     |
+----------------------+---------------------------+------------------------------------------------+
| Java / C# /          | Отдельная конструкция     | В Java класс использует `implements`.          |
| TypeScript           | `interface`               | Служит альтернативой множественному            |
|                      |                           | наследованию классов.                          |
+----------------------+---------------------------+------------------------------------------------+
| Python               | Абстрактный класс (ABC)   | Методы объявляются с `@abstractmethod`,        |
|                      |                           | но без реализации.                             |
+----------------------+---------------------------+------------------------------------------------+
| C++                  | Чистый абстрактный класс  | Отдельной конструкции `interface` нет.         |
|                      |                           | Интерфейс = класс с виртуальными               |
|                      |                           | методами (`= 0`).                              |
+----------------------+---------------------------+------------------------------------------------+
| Delphi               | Конструкция `interface`   | Введена для работы с COM (Microsoft).          |
+----------------------+---------------------------+------------------------------------------------+
```
