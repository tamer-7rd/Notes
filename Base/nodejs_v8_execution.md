# Как Node.js выполняет JavaScript на V8

## Уровень 1: Что такое V8?

**V8** — это движок (engine), который превращает твой JavaScript-код в инструкции для процессора.

### Простая аналогия

Представь автомобиль:
- **Твой код** — это бензин
- **V8** — это двигатель
- **Процессор** — это колёса

V8 берёт твой код (бензин) и превращает его в движение (выполнение).

---

## Уровень 2: Этапы выполнения кода

Когда ты запускаешь `node app.js`, происходит магия в несколько этапов:

```
Твой код (app.js)
      ↓
1. ПАРСИНГ
      ↓
2. AST (дерево)
      ↓
3. IGNITION (интерпретатор)
      ↓
4. BYTECODE
      ↓
5. Выполнение
      ↓
6. TURBOFAN (JIT-компилятор)
      ↓
7. Машинный код
```

Давай разберём каждый этап подробно!

---

## Этап 1: Парсинг (Parsing)

### Что происходит?
V8 читает твой код как текст и проверяет синтаксис.

### Пример

**Твой код:**
```javascript
const name = "Tamerlan";
console.log(name);
```

**Парсер проверяет:**
- Есть ли все скобки?
- Правильно ли написаны ключевые слова?
- Нет ли синтаксических ошибок?

**Если ошибка:**
```javascript
const name = "Tamerlan"  // Забыл точку с запятой (в строгом режиме)
console.log(name;        // Лишняя скобка
```

Парсер скажет: **SyntaxError!** ❌

---

## Этап 2: AST (Abstract Syntax Tree)

### Что это?
Парсер превращает твой код в **дерево** — структуру данных, с которой удобно работать.

### Пример

**Твой код:**
```javascript
const sum = 5 + 10;
```

**AST (упрощённо):**
```
VariableDeclaration
  ├─ kind: "const"
  ├─ name: "sum"
  └─ value: BinaryExpression
       ├─ operator: "+"
       ├─ left: Literal (5)
       └─ right: Literal (10)
```

**Зачем?** Дерево удобнее обрабатывать, чем текст.

---

## Этап 3: Ignition — интерпретатор

### Что делает?
Ignition берёт AST и превращает его в **bytecode** (промежуточный код).

### Что такое bytecode?

**Bytecode** — это не машинный код, но уже не JavaScript. Это инструкции для виртуальной машины V8.

**Пример:**

**Твой код:**
```javascript
function add(a, b) {
    return a + b;
}
```

**Bytecode (упрощённо):**
```
LdaNamedProperty a
Add b
Return
```

**Зачем bytecode?**
- Компактнее, чем JavaScript
- Быстрее выполняется
- Легче оптимизировать

---

## Этап 4: Выполнение bytecode

Ignition (интерпретатор) выполняет bytecode построчно.

```javascript
const a = 5;
const b = 10;
const sum = a + b;
console.log(sum);
```

**Что происходит:**
1. Создаётся переменная `a`, значение `5`
2. Создаётся переменная `b`, значение `10`
3. Складываются `a` и `b`, результат в `sum`
4. Вызывается `console.log` с `sum`

**Это медленно**, но работает!

---

## Этап 5: TurboFan — JIT-компилятор (магия!)

### Проблема
Если функция вызывается 1000 раз, интерпретатор будет выполнять bytecode 1000 раз — это медленно.

### Решение: JIT (Just-In-Time) компиляция

V8 следит за кодом:
- "О, эта функция вызывается часто!"
- "Давай скомпилируем её в машинный код!"

### Пример

**Твой код:**
```javascript
function add(a, b) {
    return a + b;
}

// Вызывается 10,000 раз
for (let i = 0; i < 10000; i++) {
    add(i, i + 1);
}
```

**Что происходит:**

1. **Первые вызовы** (холодный код):
   - Ignition выполняет bytecode
   - Медленно, но работает

2. **После ~100 вызовов** (тёплый код):
   - V8: "Эта функция популярная!"
   - TurboFan компилирует в машинный код

3. **Последующие вызовы** (горячий код):
   - Выполняется машинный код
   - **В 10-100 раз быстрее!** 🚀

### Оптимизация и деоптимизация

**Оптимизация:**
```javascript
function add(a, b) {
    return a + b;
}

add(5, 10);      // V8: "a и b — числа"
add(20, 30);     // V8: "Опять числа!"
add(100, 200);   // V8: "Всегда числа! Оптимизирую!"
```

TurboFan создаёт машинный код для сложения **чисел**.

**Деоптимизация:**
```javascript
add("Hello", "World");  // V8: "WTF? Строки?! 😱"
```

V8 **откатывает** оптимизацию и возвращается к bytecode.

**Урок:** Используй одинаковые типы для производительности!

## Этап 6: Сборка мусора (Garbage Collection)

### Что это?
JavaScript автоматически удаляет неиспользуемые объекты из памяти.

### Пример

```javascript
function createUser() {
    const user = { name: "Tamerlan", age: 25 };
    return user.name;
}

const name = createUser();
// Объект user больше не нужен — V8 удалит его
```

### Как работает?

V8 использует **поколенческую сборку мусора**:

1. **Young Generation** (молодое поколение):
   - Новые объекты попадают сюда
   - Сборка мусора происходит часто и быстро

2. **Old Generation** (старое поколение):
   - Объекты, которые живут долго
   - Сборка мусора происходит редко

**Аналогия:** Как уборка в доме:
- Кухня (Young) — убираешь каждый день
- Чердак (Old) — убираешь раз в год

### Проблема: утечки памяти

**Плохой код:**
```javascript
const cache = {};

function addToCache(key, value) {
    cache[key] = value;  // Объекты накапливаются!
}

// Вызывается миллион раз
for (let i = 0; i < 1000000; i++) {
    addToCache(i, { data: "..." });
}

// cache растёт и растёт — утечка памяти! 💥
```

**Хороший код:**
```javascript
const cache = new Map();

function addToCache(key, value) {
    if (cache.size > 1000) {
        const firstKey = cache.keys().next().value;
        cache.delete(firstKey);  // Удаляем старые
    }
    cache.set(key, value);
}
```

## Полная картина: от кода до выполнения

```
1. Ты пишешь: app.js
      ↓
2. Запускаешь: node app.js
      ↓
3. Node.js загружает V8
      ↓
4. V8 парсит код → AST
      ↓
5. Ignition создаёт bytecode
      ↓
6. Ignition выполняет bytecode
      ↓
7. Если код "горячий" → TurboFan компилирует в машинный код
      ↓
8. Машинный код выполняется на процессоре (быстро!)
      ↓
9. Garbage Collector чистит память
      ↓
10. Программа завершается
```

## Практический пример: оптимизация

### Плохой код (медленный)

```javascript
function process(items) {
    for (let i = 0; i < items.length; i++) {
        // Разные типы — V8 не может оптимизировать!
        if (typeof items[i] === 'number') {
            items[i] = items[i] * 2;
        } else {
            items[i] = items[i].toUpperCase();
        }
    }
}

process([1, "hello", 2, "world"]);
```

### Хороший код (быстрый)

```javascript
function processNumbers(numbers) {
    for (let i = 0; i < numbers.length; i++) {
        numbers[i] = numbers[i] * 2;  // Всегда числа!
    }
}

function processStrings(strings) {
    for (let i = 0; i < strings.length; i++) {
        strings[i] = strings[i].toUpperCase();  // Всегда строки!
    }
}

processNumbers([1, 2, 3, 4]);
processStrings(["hello", "world"]);
```

**Почему быстрее?**
- V8 видит: "Всегда числа!" или "Всегда строки!"
- TurboFan создаёт оптимизированный машинный код
- Код выполняется в 10-100 раз быстрее!

## Главные выводы

### Этапы выполнения
1. **Парсинг** — проверка синтаксиса
2. **AST** — дерево кода
3. **Bytecode** — промежуточный код
4. **Интерпретация** — медленное выполнение
5. **JIT-компиляция** — быстрое выполнение горячего кода
6. **Garbage Collection** — автоматическая очистка памяти

### Как писать быстрый код
- ✅ Используй одинаковые типы в функциях
- ✅ Избегай изменения типов переменных
- ✅ Не создавай утечки памяти
- ✅ Используй современные структуры (Map, Set)

### Когда происходит оптимизация
- **Build-time:** Нет (V8 работает в runtime)
- **Run-time:** Да! (JIT-компиляция во время выполнения)
