# Хостинг: минимальный конспект для программиста

Этот конспект — **ровно тот объём**, который нужно понимать разработчику. Не DevOps, не администратору, а **программисту**.

---

## 1. Главный принцип

**Язык программирования ≠ тип хостинга**

Хостинг — это **инфраструктура**, а язык — **инструмент внутри кода**.

Твоя задача как программиста — понимать:
- какой **тип сайта** у тебя
- какой **тип хостинга** ему подходит
- **где заканчивается твоя ответственность**

---

## 2. Типы сайтов (это основа)

### 2.1 Статический сайт

**Что это:**
- Готовые файлы: HTML, CSS, JS
- Сервер ничего не вычисляет
- Просто отдаёт файлы браузеру

**Как появляется:**
- React + Vite → `npm run build` → `dist/`
- Или обычный HTML/CSS/JS

**Примеры:**
- сайты-визитки
- лендинги
- корпоративные сайты без личных кабинетов

**Где хостится:**
- Netlify
- любой shared-хостинг (cPanel)
- CDN

---

### 2.2 Динамический сайт

**Что это:**
- Есть серверный код
- Код выполняется **на сервере**
- Есть логика, база данных, авторизация

**Примеры языков:**
- PHP
- Python (Django, Flask, FastAPI)
- Node.js
- Java, Go

**Где хостится:**
- VPS
- Cloud / PaaS (Render, Railway, Fly.io)

---

## 3. Что такое PHP (чётко и без мифов)

### 3.1 PHP — это

- **Серверный язык программирования**
- Работает **на сервере**, не в браузере
- Генерирует HTML **на каждый запрос**

### 3.2 Как работает PHP-сайт

1. Браузер запрашивает страницу
2. Сервер запускает PHP-код
3. PHP:
   - может обратиться к базе данных
   - проверить пользователя
   - собрать страницу
4. PHP **формирует HTML**
5. Браузер получает готовый HTML

**Важно:**
- Обычно **нет стадии build**, как в Vite
- HTML генерируется **на лету**, а не заранее

---

### 3.3 PHP ≠ PHP-хостинг

**PHP-хостинг** — это:
- тип услуги (shared hosting)
- инфраструктура с cPanel
- исторически заточен под PHP

Это **не требование**, чтобы сайт был написан на PHP.

Статический сайт можно спокойно разместить на PHP-хостинге — PHP просто не используется.

---

## 4. Типы хостинга (только то, что нужно знать)

### 4.1 Shared hosting («PHP-host»)

**Что это:**
- дешёвый массовый хостинг
- папка `public_html`
- PHP работает автоматически

**Подходит для:**
- PHP-сайтов
- статических сайтов

**НЕ подходит для:**
- Python backend
- Node backend
- приложений с постоянным процессом

---

### 4.2 Static hosting (Netlify и аналоги)

**Что это:**
- хостинг только для статики
- CDN, HTTPS из коробки

**Подходит для:**
- React/Vite build
- лендингов

---

### 4.3 Cloud / VPS / PaaS

**Что это:**
- сервер или платформа
- код работает постоянно

**Нужно для:**
- Python backend
- Node backend
- API

---

## 5. Где проходит граница ответственности программиста

### Твоя зона ответственности

- код
- архитектура сайта
- сборка (build)
- понимание, **какой хостинг нужен**

### НЕ твоя зона (если не оговорено отдельно)

- DNS
- серверная безопасность
- SSL
- аптайм
- почта
- cPanel

---

## 6. Ключевые фразы, которые должен уметь говорить программист

- **«Сайт статический, сервер не нужен»**
- **«PHP не используется, есть готовый build»**
- **«Для backend нужен cloud / VPS»**
- **«Хостинг и инфраструктура — зона провайдера»**

---

## 7. Мини-таблица для памяти

| Тип проекта | Хостинг |
|-----------|--------|
| Статика | Netlify, cPanel |
| PHP | PHP-host (cPanel) |
| Python / Node | Cloud / VPS |

---

## 8. Финальная установка

Как программисту тебе **не нужно**:
- быть DevOps
- разбираться в сетях
- заниматься кибербезопасностью серверов

Тебе нужно **понимать архитектуру своего проекта** и **говорить на правильном уровне абстракции**.

Этого достаточно, чтобы быть профессионалом.


**Шаги после настройки домена**

Покупка домена и хостинга (yer.az): Да, это старт. У тебя есть «имя» и есть «железо».

Настройка Name Servers (DNS Servers) у регистратора: * Это самый важный первый шаг. Ты идешь туда, где купил домен, и говоришь: «Слушайте всех, кто сидит на nizami.yer.az и nasimi.yer.az (например)».

Этим ты передаешь «пульт управления» своим доменом хостингу yer.az.

Настройка в cPanel (A-записи, MX-записи, это просто панель управления-интерфейс): * Поскольку ты указал Name Servers хостинга, теперь cPanel становится твоим пультом управления.

Когда ты там пишешь A-запись, ты физически обновляешь базу данных на тех самых серверах nizami.yer.az.

Теперь весь мир знает: если постучать к этим «ребятам» (NS), они выдадут IP твоего сайта.

Заход на сайт (Процесс в интернете):

Браузер спрашивает у глобальной сети: «Где твойсайт.com?».

Сеть отвечает: «Не знаю IP, но знаю, что тебе нужно спросить у nizami.yer.az».

Браузер идет к nizami.yer.az, и тот говорит: «А, этот! Его IP — 1.2.3.4».

Финал (HTTP/HTTPS):

Браузер берет этот IP (1.2.3.4) и стучится в него напрямую.

Там его встречает сервер yer.az (программа Apache или Nginx установленная на физический сервер (программа тоже сервер называется)), видит запрос и по протоколу HTTP/HTTPS отдает тебе файлы сайта.
