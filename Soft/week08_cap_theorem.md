# CAP-теорема — для Junior

## 🎯 Что такое CAP-теорема?

**CAP-теорема** говорит: в распределённой системе невозможно одновременно гарантировать все три свойства:

- **C** — Consistency (Согласованность)
- **A** — Availability (Доступность)
- **P** — Partition Tolerance (Устойчивость к разделению)

**Можно выбрать только 2 из 3.**

---

## 📝 Что значит каждая буква?

### C — Consistency (Согласованность)
```
Все узлы видят одинаковые данные в одно время.
Если записал данные — все сразу их увидят.
```

**Пример:** Ты обновил профиль. Согласованность = все серверы сразу покажут новые данные.

---

### A — Availability (Доступность)
```
Система всегда отвечает на запросы.
Даже если часть серверов упала — остальные работают.
```

**Пример:** Сайт всегда загружается, даже если один из серверов недоступен.

---

### P — Partition Tolerance (Устойчивость к разделению)
```
Система продолжает работать, даже если связь 
между серверами прервана.
```

**Пример:** Серверы в Москве и Лондоне потеряли связь друг с другом, но каждый продолжает обслуживать пользователей.

---

## 🔄 Почему нельзя все три?

Представь: у тебя два сервера — в Москве и в Лондоне.

### Сценарий: Связь между серверами пропала (Partition)

**Если выбираешь C (Согласованность):**
```
- Пользователь в Москве обновил профиль
- Московский сервер не может сообщить об этом Лондону
- Лондонский сервер отказывается отвечать, пока не синхронизируется
- ❌ Теряем Availability (Доступность)
```

**Если выбираешь A (Доступность):**
```
- Оба сервера продолжают работать
- Московский сервер показывает новые данные
- Лондонский сервер показывает старые данные
- ❌ Теряем Consistency (Согласованность)
```

## 🗄️ Примеры баз данных

### CP (Consistency + Partition Tolerance)

**Жертвуем:** Доступность

**Базы:** PostgreSQL, MySQL (в кластере), MongoDB (с определёнными настройками)

**Когда использовать:**
- Банковские транзакции (нельзя показать разный баланс)
- Системы бронирования (нельзя продать одно место дважды)

**Пример:**
```
Банк: если связь между серверами пропала, 
лучше показать "сервис недоступен", чем неправильный баланс.
```

---

### AP (Availability + Partition Tolerance)

**Жертвуем:** Согласованность (временно)

**Базы:** Cassandra, DynamoDB, CouchDB

**Когда использовать:**
- Социальные сети (лайки могут "догнать" позже)
- Корзина в интернет-магазине (можно синхронизировать потом)

**Пример:**
```
Twitter: если ты поставил лайк, твой друг может увидеть его 
через несколько секунд — это нормально.
```

---

### CA (Consistency + Availability)

**Жертвуем:** Устойчивость к разделению

**Базы:** Традиционные СУБД на одном сервере (PostgreSQL, MySQL)

**Когда использовать:**
- Небольшие приложения на одном сервере
- Когда разделение сети маловероятно

**Проблема:**
```
В реальности сеть может упасть. Поэтому CA — редкий выбор 
для распределённых систем.
```

## 🎬 Как объяснить на собеседовании

### Короткий ответ (30 секунд):
```
"CAP-теорема говорит, что в распределённой системе 
нельзя одновременно гарантировать согласованность, 
доступность и устойчивость к разделению сети.

Приходится выбирать: CP-системы (как PostgreSQL) 
жертвуют доступностью ради согласованности. 
AP-системы (как Cassandra) жертвуют согласованностью 
ради доступности."
```

### С примером:
```
"Например, в банке важна согласованность — нельзя показать 
разный баланс на разных серверах. Поэтому банки используют 
CP-системы: лучше отказать в обслуживании, чем показать 
неправильные данные.

А в соцсетях важнее доступность — пользователь должен видеть ленту. 
Если лайк появится с задержкой в секунду — это не критично. 
Поэтому используют AP-системы."
```

## ❓ Частые вопросы на собеседовании

### "Какую базу выбрал бы для интернет-магазина?"
```
"Зависит от функции:
- Для заказов и оплаты — CP (PostgreSQL), 
  потому что нельзя продать товар дважды
- Для отзывов и рекомендаций — AP (можно Cassandra),
  потому что задержка не критична"
```

### "Что такое eventual consistency?"
```
"Это когда данные становятся согласованными 'в конце концов', 
но не мгновенно. AP-системы используют этот подход: 
данные синхронизируются между узлами с небольшой задержкой."
```

## 🎓 Главное:

1. **CAP:** Consistency, Availability, Partition Tolerance — выбери 2 из 3
2. **CP:** Банки, транзакции — важна согласованность
3. **AP:** Соцсети, лайки — важна доступность
4. **Partition:** В реальности сеть может упасть, поэтому P обычно нужен
5. **Выбор зависит от бизнеса:** Что важнее — всегда работать или всегда быть правым?

**Запомни:** CAP — это про компромиссы. Нет "лучшего" выбора, есть подходящий для задачи!
