# Презентация фичи на демо — для Junior

## 🎯 Что такое демо?

**Demo (демонстрация)** — это показ готовой фичи команде или заказчику. Цель — показать, что сделано и как это работает.

**Когда бывает:**
- В конце спринта (Sprint Demo)
- При завершении задачи
- На встрече с заказчиком

---

## 📝 Структура демо (5-10 минут)

### 1. Контекст (30 сек)
```
"Напомню задачу: нужно было [что сделать].
Это важно, потому что [зачем это пользователю]."
```

### 2. Что сделано (30 сек)
```
"Я реализовал [список основных пунктов]:
- Первая часть
- Вторая часть
- Третья часть"
```

### 3. Демонстрация (3-5 мин)
```
"Сейчас покажу, как это работает..."
[Показываешь на экране]
```

### 4. Ограничения / Что не сделано (30 сек)
```
"Пока не реализовано [что].
Это запланировано на [когда]."
```

### 5. Вопросы (1-2 мин)
```
"Есть вопросы?"
```

---

## 🎬 Пример демо

### Задача: Форма регистрации

```
КОНТЕКСТ:
"Задача была сделать форму регистрации с валидацией.
Это нужно, чтобы пользователи могли создавать аккаунты."

ЧТО СДЕЛАНО:
"Реализовал:
- Форму с полями email и пароль
- Валидацию на клиенте и сервере
- Сообщения об ошибках
- Редирект после успешной регистрации"

ДЕМОНСТРАЦИЯ:
"Открываю страницу регистрации...
Вот форма. Если ввести невалидный email — появляется ошибка.
Если пароль короткий — тоже ошибка.
Теперь ввожу корректные данные... Отправляю...
Видим редирект на главную и пользователь создан."

ОГРАНИЧЕНИЯ:
"Пока не сделал:
- Подтверждение email (в следующем спринте)
- Регистрацию через Google (в бэклоге)"

ВОПРОСЫ:
"Есть вопросы или пожелания?"
```

## 💡 Советы для хорошего демо

### 1. Подготовься заранее
```
- Проверь, что всё работает
- Подготовь тестовые данные
- Закрой лишние вкладки
- Увеличь шрифт в браузере/IDE
```

### 2. Показывай user flow
```
❌ "Вот кнопка, вот форма, вот поле..."
✅ "Пользователь заходит на страницу, видит форму, 
    вводит данные, нажимает кнопку, получает результат."
```

### 3. Говори, что делаешь
```
❌ *молча кликаешь*
✅ "Сейчас нажму кнопку 'Отправить'... 
    Видим, что появилось сообщение об успехе."
```

### 4. Показывай edge cases
```
"А если ввести неправильный email? Вот, появляется ошибка.
А если оставить поле пустым? Тоже валидация срабатывает."
```

### 5. Будь честен об ограничениях
```
✅ "Пока работает только для одного пользователя, 
    многопользовательский режим в следующем спринте."
```

---

## ❌ Частые ошибки

### 1. Нет подготовки
```
❌ "Секунду, сейчас найду где это... Ой, не работает..."
✅ Проверь всё за 15 минут до демо
```

### 2. Показ кода вместо результата
```
❌ "Вот тут я написал функцию validateEmail..."
✅ "Если ввести неправильный email — появляется ошибка."
```

### 3. Слишком много деталей
```
❌ "Здесь я использовал useState, потом useEffect, 
    потом создал кастомный хук..."
✅ "Валидация работает в реальном времени."
```

### 4. Скрытие проблем
```
❌ "Всё работает отлично" (когда есть баги)
✅ "Есть известный баг с [чем], исправлю в этом спринте."
```

### 5. Нет контекста
```
❌ "Вот кнопка, вот форма."
✅ "Эта форма нужна, чтобы пользователь мог..."
```

## 🎯 Что если что-то сломалось?

### План Б:
```
"Кажется, сервер не отвечает. 
У меня есть скриншоты/видео, могу показать."
```

### Честность:
```
"Странно, утром работало. 
Могу показать код и объяснить логику, 
а рабочую версию покажу позже."
```

### Не паниковать:
```
"Техника иногда подводит. 
Давайте я быстро перезапущу сервер..."
```

## 📋 Чек-лист перед демо

### За день до:
- [ ] Всё работает?
- [ ] Есть тестовые данные?
- [ ] Знаю порядок показа?

### За 15 минут до:
- [ ] Проверил, что приложение запущено?
- [ ] Закрыл лишние вкладки?
- [ ] Увеличил шрифт?
- [ ] Есть резервный план (скриншоты)?

### Во время демо:
- [ ] Дал контекст?
- [ ] Показываю user flow, а не кнопки?
- [ ] Говорю, что делаю?
- [ ] Честен об ограничениях?

---

## 🎓 Главное:

1. **Контекст:** Напомни, зачем это нужно
2. **User flow:** Показывай путь пользователя, а не кнопки
3. **Комментируй:** Говори, что делаешь
4. **Честность:** Не скрывай ограничения и баги
5. **Подготовка:** Проверь всё заранее + имей план Б

**Запомни:** Хорошее демо — это не про "вау-эффект", а про понятную демонстрацию того, что задача решена!
