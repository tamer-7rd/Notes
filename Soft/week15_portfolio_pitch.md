# Финальный питч портфолио (Week 15)

## Цель
Научиться за 3-5 минут **продать** своё портфолио целиком — не один проект, а себя как разработчика. Это не "расскажи о себе" (week 02) и не "презентация проекта" (week 03/13). Это **стратегический питч**: ты показываешь путь, рост и систему, а не разрозненные репозитории.

> Формат: Senior объясняет Junior-у (стаж ~1 год), как превратить набор проектов в цельную историю.

---

## 1. Зачем нужен питч портфолио

> Junior: "У меня есть GitHub, пусть смотрят код."
> Senior: "Никто не будет 30 минут разбирать твой GitHub. Ты должен сам расставить акценты."

```
  Что видит рекрутер              Что должен увидеть
  без твоего питча:               после твоего питча:
  +---------------------------+   +---------------------------+
  | - 15 репозиториев         |   | - 3 ключевых проекта      |
  | - todo-app                |   | - рост от todo к fullstack|
  | - calculator              |   | - осознанный выбор стека  |
  | - unnamed-project-2       |   | - CI/CD, тесты, деплой    |
  | - fork чужого проекта     |   | - умение объяснить "зачем"|
  | - "что тут вообще?"       |   | - готовность к реальным   |
  +---------------------------+   |   задачам                 |
                                  +---------------------------+
```

**Формула:** Портфолио — это не список проектов. Это **история твоего роста**, рассказанная через код.

---

## 2. Структура питча (3-5 минут)

```
  +------------------------------------------------------------------+
  |                   СТРУКТУРА PORTFOLIO PITCH                       |
  +------------------------------------------------------------------+
  |                                                                   |
  |  [1] HOOK             "Я — fullstack dev, и вот моя история"     |
  |       15 сек           Кто ты + одна цепляющая фраза              |
  |                                                                   |
  |  [2] ПУТЬ             "От первого проекта до продакшн-кода"      |
  |       30-45 сек        3 точки роста, не биография                 |
  |                                                                   |
  |  [3] КЛЮЧЕВОЙ         "Вот мой главный проект — и почему"        |
  |      ПРОЕКТ            Проблема → Решение → Стек → Результат      |
  |       60-90 сек                                                    |
  |                                                                   |
  |  [4] ИНЖЕНЕРНАЯ       "Вот как я пишу код на самом деле"          |
  |      КУЛЬТУРА          Тесты, CI/CD, код-ревью, Git-flow         |
  |       30-45 сек                                                    |
  |                                                                   |
  |  [5] ВЕКТОР           "Вот куда я расту"                          |
  |       15-30 сек        Что изучаешь сейчас, какие задачи хочешь   |
  |                                                                   |
  +------------------------------------------------------------------+
```

## 3. Разбор каждого блока

### Блок 1: Hook (15 сек)

**Задача:** Зацепить внимание. Не "Привет, меня зовут...", а сразу ценность.

```
  +---------------------------------------------------------------------------+
  | Плохо                            | Хорошо                                  |
  +---------------------------------------------------------------------------+
  | "Привет, я Тамерлан, я учусь    | "Я fullstack-разработчик. За последний  |
  |  программировать год."           |  год я прошёл путь от todo-приложения   |
  |                                  |  до продакшн-проекта с CI/CD, тестами   |
  |                                  |  и деплоем на VPS."                     |
  +---------------------------------------------------------------------------+
```

**Принцип:** Первые 15 секунд — это trailer к фильму. Если trailer скучный — фильм не смотрят.

---

### Блок 2: Путь / Arc роста (30-45 сек)

**Задача:** Показать не ЧТО ты делал, а КАК ты рос. Выбери 3 точки.

```
  Точка 1                  Точка 2                   Точка 3
  (начало)                 (прорыв)                  (сейчас)
     |                        |                         |
     v                        v                         v
  "Первый проект —         "Понял, что код без       "Сейчас мой проект —
   React + Express,         тестов и CI — это          fullstack с Docker,
   всё в одном файле,       песочный замок.            GitHub Actions, PostgreSQL,
   без тестов,              Переписал с нуля:          и мониторингом. Деплой
   деплой по FTP."          добавил Jest, ESLint,      на VPS через CI/CD."
                            разделил на слои."
```

**Зачем:** Интервьюер видит, что ты **способен учиться**. Для junior-а это важнее, чем знать 15 фреймворков.

Шаблон:
```
"Год назад я начал с [что]. Быстро понял, что [проблема/урок].
Это привело меня к [переломный момент]. Сейчас я [текущий уровень]."
```

---

### Блок 3: Ключевой проект (60-90 сек)

**Задача:** Один проект — глубоко. Не три проекта поверхностно.

Структура STAR для проекта:

```
  +-------------------------------------------------------------------+
  |  S — Situation    "Какую проблему решает проект?"                  |
  |  T — Task         "Какая была моя задача / роль?"                  |
  |  A — Action       "Что конкретно я сделал? Какие решения принял?"  |
  |  R — Result       "Какой результат? Что можно потрогать?"          |
  +-------------------------------------------------------------------+
```

Пример:
```
"Мой ключевой проект — TaskFlow, менеджер задач для небольших команд.

 Проблема:  Trello слишком перегружен для маленьких команд,
            а todo-листы не дают видеть прогресс.

 Решение:   Kanban-доска с drag-and-drop, фильтрами
            и email-уведомлениями.

 Стек:      React + TypeScript / Node.js + Express / PostgreSQL
            Redis для сессий / Docker / GitHub Actions CI/CD

 Решение:   Самым сложным было реализовать real-time обновление
            доски. Сначала делал polling каждые 5 секунд —
            нагрузка росла линейно. Перешёл на WebSocket —
            нагрузка стала константной.

 Результат: Задеплоен на VPS, работает, покрыт тестами на 70%.
            Ссылка: taskflow.example.com"
```

**На интервью спросят:** "Почему PostgreSQL, а не MongoDB?"
Ответ: "Данные связаны — юзер → доска → колонка → задача. Реляционная модель + JOIN-ы здесь логичнее, чем вложенные документы."

---

### Блок 4: Инженерная культура (30-45 сек)

**Задача:** Показать, что ты пишешь код **как профессионал**, а не как студент.

```
  +---------------------+----------------------------------------------+
  | Что упомянуть       | Как сказать                                   |
  +---------------------+----------------------------------------------+
  | Git-flow            | "Работаю через feature-ветки, PR и squash    |
  |                     |  merge. Main всегда в рабочем состоянии."     |
  +---------------------+----------------------------------------------+
  | CI/CD               | "На каждый PR автоматически запускаются       |
  |                     |  линтер, тесты и билд через GitHub Actions."  |
  +---------------------+----------------------------------------------+
  | Тесты               | "Пишу unit-тесты на Jest/Vitest. Покрытие     |
  |                     |  ключевой логики — 70%+."                     |
  +---------------------+----------------------------------------------+
  | Code Review         | "Практикую self-review перед каждым PR.       |
  |                     |  В командном проекте делал ревью коллегам."   |
  +---------------------+----------------------------------------------+
  | Чистый код          | "Следую принципам SOLID, DRY. Использую       |
  |                     |  ESLint + Prettier для единого стиля."        |
  +---------------------+----------------------------------------------+
```

**Почему это важно:** 90% junior-ов покажут проект. 10% покажут **процесс**. Ты хочешь быть в тех 10%.

---

### Блок 5: Вектор роста (15-30 сек)

**Задача:** Показать, что ты не остановился и знаешь, куда идёшь.

```
  Сейчас изучаю:                    Хочу решать задачи:
  +-----------------------------+   +-----------------------------+
  | - Docker + Docker Compose   |   | - Проектирование API        |
  | - Основы System Design      |   | - Работа с нагрузкой        |
  | - TypeScript углублённо     |   | - Микросервисная архитектура |
  | - PostgreSQL оптимизация    |   | - Командная разработка      |
  +-----------------------------+   +-----------------------------+
```

Шаблон:
```
"Сейчас я углубляюсь в [что]. Мне интересно работать над задачами,
связанными с [какими]. В вашей команде меня привлекает [что именно]."
```

**Последнее предложение** — адаптируй под конкретную компанию. Всегда.

  |    |                                  | ты сам обесцениваешь себя.                 |

## 5. Полный пример питча (3 минуты)

```
"Я fullstack-разработчик на React и Node.js. За последний год я прошёл путь
от первого todo-приложения до продакшн-проекта с CI/CD, тестами и деплоем
на VPS.

Начинал я с простых проектов — React-приложения без бэкенда, код в одном
файле, деплой через перетаскивание файлов на хостинг. Довольно быстро понял,
что без структуры, тестов и автоматизации проект разваливается при любом
изменении. Это стало поворотным моментом — я переписал свой проект с нуля,
разделил на слои, добавил тесты и настроил CI.

Мой ключевой проект — TaskFlow, это Kanban-доска для небольших команд.
Проблема: Trello перегружен для маленьких команд, а простые todo-листы
не дают видеть прогресс по задачам.

Стек: React с TypeScript на фронте, Node.js с Express на бэке, PostgreSQL
как основная база, Redis для сессий. Всё завёрнуто в Docker, деплой через
GitHub Actions на VPS.

Самым интересным вызовом было real-time обновление доски. Начал с polling —
клиент дёргал API каждые 5 секунд. При 10 юзерах это уже создавало
заметную нагрузку. Переделал на WebSocket — нагрузка стала константной,
обновления мгновенные.

Что касается процесса — я работаю через feature-ветки с PR. На каждый PR
запускается линтер, тесты и билд через GitHub Actions. Пишу unit-тесты
на Vitest, покрытие ключевой бизнес-логики — около 70%.

Сейчас углубляюсь в System Design и Docker. Мне интересны задачи, связанные
с проектированием API и работой с нагрузкой. В вашей компании меня привлекает
[продукт / стек / команда].

Вот ссылка на GitHub и задеплоенный проект — буду рад обсудить детали."
```

## 6. Как подготовить GitHub к питчу

Прежде чем кидать ссылку — приведи GitHub в порядок:

```
  +---------------------------+----------------------------------------------+
  | Что сделать               | Зачем                                         |
  +---------------------------+----------------------------------------------+
  | Запинить 3 лучших проекта | Рекрутер видит главное, а не 30 форков       |
  +---------------------------+----------------------------------------------+
  | README с скриншотами      | "Картинка стоит тысячи слов"                 |
  |  и инструкцией запуска    |  Если нет README — проект не существует       |
  +---------------------------+----------------------------------------------+
  | Удалить / архивировать    | calculator-2023, test-project, untitled —     |
  |  мусорные репо            |  это шум, который мешает                      |
  +---------------------------+----------------------------------------------+
  | Описание в каждом репо    | Одна строка: "Kanban board built with         |
  |                           |  React + Node.js + PostgreSQL"                |
  +---------------------------+----------------------------------------------+
  | Живая ссылка (deploy)     | Ничто не убеждает лучше, чем                  |
  |                           |  работающий продукт                           |
  +---------------------------+----------------------------------------------+
  | Чистая Git-история        | "feat: add drag-and-drop" лучше, чем          |
  |                           |  "fix", "asdfg", "WIP WIP WIP"               |
  +---------------------------+----------------------------------------------+
```

## 7. Адаптация под формат

### Если просят "покажите портфолио" (5 мин):
```
Используй полную структуру: Hook → Путь → Проект → Культура → Вектор.
```

### Если просят "расскажите о проекте" (2 мин):
```
Только блок 3 (STAR): Проблема → Задача → Решение → Результат.
```

### Если просят "почему мы должны вас взять?" (1 мин):
```
Hook + Культура + Вектор. Без деталей проекта — фокус на процессе и росте.
```

### Если это README на GitHub (текст):
```
То же самое, но в письменном виде:
- Заголовок с hook
- Скриншот / GIF
- Стек (badges)
- Как запустить
- Архитектура (ASCII-диаграмма)
- Что я узнал
```

## 8. Чек-лист перед питчем

- [ ] GitHub приведён в порядок (3 пиннед-проекта, README, нет мусора)?
- [ ] Я могу рассказать свою "arc роста" за 30 секунд?
- [ ] Я выбрал ОДИН ключевой проект и знаю его вдоль и поперёк?
- [ ] Я могу объяснить выбор каждой технологии ("почему X, а не Y")?
- [ ] Я упоминаю инженерную культуру (тесты, CI/CD, Git-flow)?
- [ ] Я рассказываю о трудностях и их решениях?
- [ ] Питч адаптирован под конкретную компанию (финальная фраза)?
- [ ] Я отрепетировал вслух минимум 5 раз и уложился в 3-5 минут?
- [ ] У проекта есть живая ссылка (деплой)?
- [ ] Я НЕ извиняюсь за свой уровень?

---

## Итого

```
  Питч портфолио = История роста + Один сильный проект + Инженерная культура
```

Интервьюер за 3 минуты должен понять три вещи:
1. Ты **умеешь учиться** (путь, а не список курсов)
2. Ты **умеешь строить** (рабочий проект, а не 10 заброшенных)
3. Ты **умеешь работать как профессионал** (тесты, CI, Git, а не "закинул по FTP")

Если он понял все три — ты прошёл.
