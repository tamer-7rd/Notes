## Часть 2: Разбор чужого кода

### 🎯 Зачем это нужно?

На работе ты будешь:
- Читать код коллег
- Делать код-ревью
- Разбираться в legacy-коде
- Фиксить баги в чужом коде

---

### 📝 Как подходить к чужому коду

#### Шаг 1: Понять цель
```
"Что этот код должен делать?"
- Прочитай название функции/файла
- Посмотри комментарии (если есть)
- Найди точку входа
```

#### Шаг 2: Найти структуру
```
"Как код организован?"
- Какие функции/классы есть?
- Как они связаны?
- Откуда приходят данные, куда уходят?
```

#### Шаг 3: Пройти по логике
```
"Что происходит шаг за шагом?"
- Начни с входной точки
- Проследи поток данных
- Отметь ключевые преобразования
```

#### Шаг 4: Задать вопросы
```
"Что непонятно?"
- Запиши вопросы
- Попробуй найти ответы в коде
- Если не нашёл — спроси автора
```

---

### 🎬 Пример разбора кода

#### Код для разбора:
```javascript
function processOrders(orders) {
  const validOrders = orders.filter(o => o.status === 'pending');
  const totals = validOrders.map(o => o.items.reduce((sum, i) => sum + i.price, 0));
  const grandTotal = totals.reduce((sum, t) => sum + t, 0);
  return { count: validOrders.length, total: grandTotal };
}
```

#### Хороший разбор:
```
"Эта функция обрабатывает заказы.

Что она делает:
1. Фильтрует заказы со статусом 'pending' (ожидающие)
2. Для каждого заказа считает сумму всех товаров
3. Складывает все суммы в общий итог
4. Возвращает количество заказов и общую сумму

Вопросы, которые бы задал автору:
- Что если orders пустой или undefined?
- Нужна ли валидация на отрицательные цены?
- Почему только 'pending', а не другие статусы?"
```

---

### 💡 Как давать обратную связь на код-ревью

#### DO (Делай):
```
✅ "Можно упростить: вместо цикла использовать reduce"
✅ "Здесь может быть null, стоит добавить проверку"
✅ "Непонятно, что делает переменная x, можно переименовать?"
```

#### DON'T (Не делай):
```
❌ "Плохой код"
❌ "Почему так криво написал?"
❌ "Я бы сделал по-другому" (без объяснения)
```

### Формула хорошего комментария:
```
[Что вижу] + [Почему это проблема] + [Как можно улучшить]

"Здесь нет проверки на null. Если придёт null, упадёт ошибка.
Можно добавить: if (!data) return [];"
```

### ❓ Вопросы на собеседовании

#### "Как ты читаешь чужой код?"
```
"Сначала смотрю на структуру — какие файлы, папки, модули.
Потом нахожу точку входа и прослеживаю поток данных.
Если что-то непонятно — читаю тесты, они часто объясняют 
ожидаемое поведение."
```

#### "Как относишься к legacy-коду?"
```
"Понимаю, что код писался в определённом контексте.
Не спешу переписывать — сначала разбираюсь, почему так сделано.
Если нужны изменения — делаю постепенно, с тестами."
```

#### "Что делаешь, если код непонятен?"
```
"Сначала пытаюсь разобраться сам: читаю, дебажу, смотрю тесты.
Если не получается — спрашиваю автора или коллегу.
Не боюсь признать, что не понимаю."
```

## 🎓 Главное:

### Роль в команде:
1. **Честность:** Говори о реальных качествах, не придумывай
2. **Примеры:** Подкрепляй слова конкретными ситуациями
3. **Открытость:** Готовность учиться и спрашивать — это плюс

### Разбор кода:
1. **Структура:** Цель → Структура → Логика → Вопросы
2. **Конструктивность:** Критикуй код, а не автора
3. **Смирение:** Не понял — спроси, это нормально

**Запомни:** Junior не должен знать всё. Важнее уметь учиться и работать с другими!
