## Конспект: Server vs Client Components

В современном React (Next.js App Router) компоненты разделены по их **ответственности**. Это сделано для того, чтобы не нагружать браузер пользователя лишней работой.

### 1. Server Components (По умолчанию)

Это компоненты-«информаторы». Они просто отдают данные.

* **Где работают:** Только на сервере (Node.js).
* **Что могут:** Напрямую обращаться к базе данных, читать файлы из папки проекта, использовать секретные API-ключи.
* **Главный плюс:** Браузер не получает ни строчки их кода. Только готовый результат. Если твой серверный компонент весит 1 МБ из-за библиотек, для пользователя он весит 0 байт.
* **Ограничения:** В них **нельзя** использовать клики, стейты (`useState`) и эффекты (`useEffect`).

### 2. Client Components (С пометкой `'use client'`)

Это компоненты-«активисты». Они отвечают за жизнь на странице.

* **Где работают:** Сначала рендерятся на сервере (как черновик), а потом «оживают» в браузере.
* **Что могут:** Реагировать на действия пользователя, менять состояние экрана, использовать браузерные фишки (localStorage, уведомления).
* **Как включить:** Написать `'use client'` в самой первой строке файла.
* **Главный минус:** Их код скачивается в браузер. Чем их больше, тем «тяжелее» сайт.

---

## Когда именно писать `'use client'`?

Используй клиентские компоненты только тогда, когда тебе нужно хотя бы одно из списка ниже:

1. **Интерактивность:** Кнопки (`onClick`), формы (`onSubmit`), ввод текста (`onChange`).
2. **Состояние (Hooks):** Если тебе нужны `useState()`, `useReducer()`, `useEffect()`.
3. **Браузерные API:** Если в коде есть `window`, `document`, `navigator` или доступ к кукам/хранилищу на стороне клиента.
4. **Специфические библиотеки:** Например, графики (Chart.js) или библиотеки анимаций (Framer Motion), которым нужен доступ к экрану в реальном времени.

## Шпаргалка: что выбрать?

| Твоя задача | Тип компонента |
| --- | --- |
| Получить список постов из базы | **Server** |
| Показать текст статьи | **Server** |
| Сделать кнопку «Лайк» | **Client** |
| Форма регистрации | **Client** |
| Скрыть API-ключ от хакеров | **Server** |
| Анимация появления меню | **Client** |

## Главное правило архитектуры

**Держи клиентские компоненты на концах веток.** Не делай всю страницу клиентской только потому, что тебе нужна одна кнопка в подвале. Оставь страницу серверной, а кнопку вынеси в отдельный файл с `'use client'` и импортируй её туда. Так ты сохранишь скорость загрузки.

> **Важно:** Ты можешь импортировать Client Component в Server Component. Но ты не можешь импортировать Server Component в Client Component (потому что серверный код не может работать в браузере).
