# Git Hooks (Хуки Гита 🪝) — для Junior

Привет! Давай разберём, как заставить Git работать за тебя.
**Git Hooks** — это скрипты, которые запускаются **автоматически** перед или после определённых событий в Git (коммит, пуш, мерж).

Представь, что это **охранник** на входе в клуб 💂‍♂️. Он проверяет твой дресс-код (код-стайл) и паспорт (тесты) перед тем, как пустить внутрь (в репозиторий).

---

## 🎯 Зачем это нужно?

Чтобы не делать рутину руками и не допускать глупых ошибок:
1. **Не пустить плохой код:** Проверить линтером, что нет ошибок.
2. **Не сломать билд:** Запустить тесты перед пушем.
3. **Красивая история:** Проверить, что сообщение коммита написано правильно (например, начинается с "JIRA-123").

---

## 🛠 Как это работает?

В каждой папке с гитом есть скрытая папка: `.git/hooks/`.
Там лежат файлы-скрипты: `pre-commit`, `pre-push` и т.д.

Если ты создашь файл `.git/hooks/pre-commit` и напишешь туда `npm test`, то Git будет запускать тесты **перед каждым коммитом**. Если тесты упадут — коммит **не создастся**.

---

## 🔝 Топ-3 самых полезных хука

### 1. `pre-commit` (Перед коммитом)
Самый популярный. Запускается, когда ты пишешь `git commit`.
**Что делать:**
- Запустить линтер (ESLint, Prettier).
- Проверить типы (TypeScript).
- Прогнать unit-тесты.

### 2. `commit-msg` (Проверка сообщения)
Запускается после ввода сообщения коммита.
**Что делать:**
- Проверить формат: "feat: add login" (Conventional Commits).
- Проверить наличие номера задачи: "PROJ-123: fix bug".

### 3. `pre-push` (Перед пушем)
Запускается, когда ты пишешь `git push`.
**Что делать:**
- Запустить **все** тесты (это долго, поэтому лучше на пуш, а не на коммит).
- Проверить, что ты не пушишь в `main` напрямую (если запрещено).

## 🐶 Husky — Стандарт индустрии

Проблема нативных хуков (`.git/hooks`) в том, что **они не пушатся в репозиторий**. Папка `.git` локальная. Твой коллега скачает проект, и у него хуков не будет.

Решение: библиотека **Husky** (для JS/Node.js проектов). Она настраивает хуки для всех разработчиков.

### Как настроить Husky (для JS проекта):

1. **Установи:**
```bash
npm install --save-dev husky
npx husky init
```

2. **Добавь хук (например, pre-commit):**
В файле `.husky/pre-commit` напиши:
```bash
npm run lint
npm test
```

Теперь любой, кто скачает проект и сделает `npm install`, автоматически получит настроенные хуки!

---

## 🛡️ Lint-staged (Друг Husky)

Запускать линтер на **весь** проект при каждом коммите — долго.
**lint-staged** позволяет проверять **только те файлы, которые ты изменил** (staged).

**Связка мечты (в package.json):**

```json
{
  "scripts": {
    "prepare": "husky"
  },
  "lint-staged": {
    "*.{js,ts}": "eslint --fix",
    "*.{css,md}": "prettier --write"
  }
}
```

В `.husky/pre-commit`:
```bash
npx lint-staged
```

Теперь Git будет автоматически чистить и проверять только твой новый код. Быстро и чисто! ✨

## 📋 Чек-лист: Нужны ли тебе хуки?

- [ ] Ты часто забываешь прогнать линтер и пушишь "грязный" код?
- [ ] Ты ломал билд на CI, потому что забыл запустить тесты локально?
- [ ] В команде есть стандарт сообщений коммитов?

**Если "да" — ставь Husky.**

---

## 🎓 Главное для Junior:

1. **Hooks** — это автоматизация. Не делай руками то, что может сделать робот.
2. **Pre-commit** — твой лучший друг. Он спасёт тебя от позора (неработающего кода в репозитории).
3. **Используй Husky** в командной работе, чтобы правила были одни для всех.
4. **Не перебарщивай.** Если pre-commit идёт 5 минут, ты начнёшь его отключать (`git commit --no-verify`). Хуки должны быть быстрыми!
