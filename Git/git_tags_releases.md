# Git Tags и Releases — для Junior

## 🎯 Что такое теги простыми словами?

**Git Tag** = это "закладка" на определённом коммите. Как закладка в книге — ты отмечаешь важное место, чтобы легко к нему вернуться.

**Зачем нужны теги:**
- Отметить версию релиза (`v1.0.0`, `v2.1.3`).
- Закрепить важный коммит (например, релиз в продакшн).
- Легко вернуться к конкретной версии проекта.

**Аналогия:** Как версия приложения в App Store (1.0, 1.1, 2.0). Тег — это способ сказать Git: "Этот коммит = версия 1.0".

---

## 🏷️ Два типа тегов

### 1. Lightweight Tag (Легковесный тег)

Просто указатель на коммит. Как закладка без описания.

```bash
git tag v1.0.0
```

**Когда использовать:** Для личных пометок, временных меток.

---

### 2. Annotated Tag (Аннотированный тег) — РЕКОМЕНДУЕТСЯ

Тег с дополнительной информацией: автор, дата, сообщение.

```bash
git tag -a v1.0.0 -m "Релиз версии 1.0.0"
```

**Когда использовать:** Для релизов, важных версий. Всегда используй этот тип для публичных релизов.

---

## 📝 Как работать с тегами

### Создать тег:

```bash
# Легковесный тег
git tag v1.0.0

# Аннотированный тег (с сообщением)
git tag -a v1.0.0 -m "Релиз версии 1.0.0"

# Тег на конкретном коммите
git tag -a v1.0.0 abc1234 -m "Релиз версии 1.0.0"
```

### Посмотреть все теги:

```bash
# Список всех тегов
git tag

# Список с фильтром
git tag -l "v1.*"
```

### Посмотреть информацию о теге:

```bash
# Информация о теге
git show v1.0.0
```

### Удалить тег:

```bash
# Удалить локально
git tag -d v1.0.0

# Удалить на удалённом репозитории
git push origin --delete v1.0.0
```

### Отправить теги на GitHub/GitLab:

```bash
# Отправить один тег
git push origin v1.0.0

# Отправить все теги
git push origin --tags
```

---

## 🚀 Что такое Releases (на GitHub/GitLab)?

**Release** = это тег + описание + файлы (архивы, бинарники).

**Разница:**
- **Tag** = просто метка на коммите.
- **Release** = тег + красивое описание + файлы для скачивания.

### Как создать Release на GitHub:

#### Вариант 1: Через веб-интерфейс

1. Перейди в репозиторий на GitHub.
2. Нажми "Releases" → "Create a new release".
3. Выбери тег (или создай новый).
4. Напиши описание (что нового в этой версии).
5. Прикрепи файлы (опционально).
6. Нажми "Publish release".

#### Вариант 2: Через Git (только тег)

```bash
# Создай тег
git tag -a v1.0.0 -m "Релиз версии 1.0.0"

# Отправь тег
git push origin v1.0.0

# Потом зайди на GitHub и создай Release из этого тега
```

---

## 💡 Практический пример

### Сценарий: Ты выпускаешь версию 1.0.0

```bash
# 1. Убедись, что все изменения закоммичены
git status

# 2. Переключись на main/master
git checkout main

# 3. Убедись, что main актуален
git pull origin main

# 4. Создай тег на текущем коммите
git tag -a v1.0.0 -m "Релиз версии 1.0.0: Добавлена авторизация и профиль пользователя"

# 5. Отправь тег на GitHub
git push origin v1.0.0

# 6. Зайди на GitHub → Releases → Create release из тега v1.0.0
```

## 🎓 Главное для Junior:

1. **Tag** = закладка на коммите (версия релиза).
2. **Annotated Tag** (с `-a`) = тег с описанием (используй для релизов).
3. **Release** = тег + описание + файлы (на GitHub/GitLab).
4. **Теги не отправляются автоматически** — нужно делать `git push origin --tags`.
5. **Для релизов:** Создай тег → отправь на GitHub → создай Release через веб-интерфейс.

**Запомни:** Тег — это способ отметить важный коммит (версию). Release — это красивое представление тега на GitHub.
