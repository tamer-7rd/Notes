# Git: Выпуск проекта в продакшн (Production Release)

> Формат: Senior объясняет Junior-а, что происходит в момент "нажатия кнопки", чтобы всё не развалилось.

---

## 1. 🚀 Разница между Dev и Prod

В разработке мы ценим **гибкость**. В продакшене — **стабильность**.

```
  Флоу деплоя:
  [Feature Branch] --(PR)--> [Main/Develop] --(Tag)--> [Production]
          ^                        ^                      ^
     "Хаос и правки"        "Стабильный код"        "Святая земля"
```

---

## 2. 🔢 Шаг 1: Версионирование (SemVer)

Не деплой "просто последний коммит". Используй теги.

**Semantic Versioning (SemVer): `v1.2.3`**
- `1` (Major): Глобальные изменения (несовместимы с прошлым).
- `2` (Minor): Новая фича.
- `3` (Patch): Фикс бага.

```bash
# Создать тег для релиза
git tag -a v1.0.0 -m "First stable release"
git push origin v1.0.0
```

---

## 3. 🔑 Шаг 2: Управление конфигами (Secrets)

**Никогда не хардкодь URL-ы или ключи!**

    +------------------------+--------------------------+--------------------------+
    | Параметр               | Development              | Production               |
    +------------------------+--------------------------+--------------------------+
    | DB_URL                 | localhost:5432           | db.production.cloud:5432 |
    | API_KEY                | test_key_123             | live_abc_987654321       |
    | DEBUG                  | True                     | False                    |
    | ALLOWED_HOSTS          | ['*']                    | ['myapp.com']            |
    +------------------------+--------------------------+--------------------------+

**Как делать правильно:**
1. В коде: `process.env.DATABASE_URL` или `os.getenv('DB_URL')`.
2. В CI/CD (GitHub Actions): добавь их в **Settings -> Secrets and Variables**.

---

## 4. 🐘 Шаг 3: Миграции Базы Данных

**Проблема:** Код задеплоился, а новая колонка в БД не создалась → сайт упал (500 Error).

**Правило:** Миграции должны идти **ДО** обновления кода или одновременно с ним.

```bash
# Типичный скрипт деплоя
git pull origin main
docker-compose run web python manage.py migrate  # Сначала миграция!
docker-compose up -d --build                     # Потом перезапуск кода
```

---

## 5. 🚬 Шаг 4: Smoke Tests

После деплоя не иди пить кофе. Сделай "дымные тесты".

**Что проверить:**
- Открывается ли главная страница?
- Работает ли логин?
- Нет ли 500-х ошибок в консоли?

```bash
# Простой способ проверить статус из терминала
curl -I https://myapp.com
# Должно быть: HTTP/2 200
```

---

## 6. 🔄 Шаг 5: Стратегия отката (Rollback)

Если всё пошло не так, у тебя должен быть план Б.

```bash
# Мгновенный откат к прошлому стабильному тегу
git checkout v0.9.9
git push --force origin main  # (в крайнем случае, если нет CI/CD)
```

**На интервью:** "Что вы сделаете, если после деплоя всё упало?"
— "Сначала я сделаю Rollback до предыдущей стабильной версии (тега), чтобы пользователи не страдали. Только потом пойду в логи выяснять причину в Staging-среде."

## 7. 🏗️ Полный цикл релиза (ASCII)

```
       РАЗРАБОТКА               СБОРКА & ТЕСТ              ДЕПЛОЙ
    +---------------+       +------------------+       +---------------+
    | git checkout  |       | run unit tests   |       | run migrations|
    | code changes  | ----> | build artifacts  | ----> | switch traffic |
    | code review   |       | security scan    |       | smoke tests   |
    +---------------+       +------------------+       +---------------+
                                     |                         |
                                     v                         v
                                [ОШИБКА?]                 [ВСЁ ОК?]
                                     |                         |
                                     v                         v
                                Стоп деплой               Удаляем старую
                                и фикс                    версию
```

---

## 8. Чек-лист "В Прод!"

- [ ] **Env vars:** Все секреты прописаны в настройках сервера.
- [ ] **Database:** Миграции готовы и протестированы.
- [ ] **Monitoring:** Настроены логи (Sentry, ELK) и алерты.
- [ ] **SSL:** Сертификат (Let's Encrypt) активен, HTTPS работает.
- [ ] **Domain:** DNS записи обновились.
- [ ] **Static:** Картинки и скрипты отдаются (CDN или Nginx).

---

## Итого

Релиз — это не случайность, а процесс. Если ты делаешь это руками — ты ошибешься. Если за тебя это делает Git тег и CI/CD пайплайн — ты Senior.
