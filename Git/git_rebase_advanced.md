# Git Rebase Продвинутый — для Junior

## 🎯 Что такое Rebase простыми словами?

**Rebase** = способ "переписать" историю коммитов, чтобы она была линейной и чистой.

**Аналогия:** Представь, ты пишешь книгу по главам. Ты написал главы 1-3, а твой друг написал главы 4-6 поверх твоих. Rebase — это способ "переписать" его главы так, будто они идут после твоих, а не поверх.

---

## 🔄 Rebase vs Merge

### Merge (Слияние):

```
main:     A---B---C---M
                \     /
feature:         D---E
```

**Результат:** История с "развилкой" и merge-коммитом.

### Rebase (Перебазирование):

```
main:     A---B---C
                    \               
feature:             D'---E'
```

**Результат:** Линейная история, как будто feature-ветка была создана после коммита C.

---

## 🛠️ Базовые команды Rebase

### 1. Rebase текущей ветки на main:

```bash
# Переключись на свою ветку
git checkout feature-branch

# Подтяни последние изменения
git fetch origin

# Перебазируй на main
git rebase origin/main
```

### 2. Rebase одной ветки на другую:

```bash
git checkout feature-branch
git rebase main
```

### 3. Отменить rebase (если что-то пошло не так):

```bash
git rebase --abort
```

## 🎨 Interactive Rebase (Интерактивный Rebase)

**Интерактивный rebase** = способ изменить последние N коммитов (объединить, переименовать, удалить).

### Команда:

```bash
# Изменить последние 3 коммита
git rebase -i HEAD~3

# Изменить все коммиты до определённого коммита
git rebase -i abc1234
```

### Что откроется в редакторе:

```
pick a1b2c3 Первый коммит
pick d4e5f6 Второй коммит
pick g7h8i9 Третий коммит
```

---

## 🔧 Команды Interactive Rebase

### `pick` — оставить как есть
```
pick a1b2c3 Первый коммит
```
**Что делает:** Оставляет коммит без изменений.

---

### `reword` — изменить сообщение коммита
```
reword a1b2c3 Первый коммит
```
**Что делает:** Откроет редактор для изменения сообщения коммита.

**Пример:**
```
# Было:
pick a1b2c3 Начал делать логин

# Стало:
reword a1b2c3 Начал делать логин
# После сохранения откроется редактор, где можно написать:
# "Реализация функционала Login"
```

---

### `squash` — объединить с предыдущим коммитом
```
pick a1b2c3 Первый коммит
squash d4e5f6 Второй коммит
```
**Что делает:** Объединяет коммит с предыдущим. Сообщения обоих коммитов сохранятся.

**Пример:**
```
# Было:
pick a1b2c3 Начал делать логин
pick d4e5f6 Поправил опечатку
pick g7h8i9 Финальные правки

# Стало:
pick a1b2c3 Начал делать логин
squash d4e5f6 Поправил опечатку
pick g7h8i9 Финальные правки

# Результат: два коммита объединятся в один
```

---

### `fixup` — объединить и удалить сообщение
```
pick a1b2c3 Первый коммит
fixup d4e5f6 Второй коммит
```
**Что делает:** То же, что `squash`, но удаляет сообщение второго коммита.

**Пример:**
```
# Было:
pick a1b2c3 Начал делать логин
pick d4e5f6 Поправил опечатку
pick g7h8i9 Забыл запятую

# Стало:
pick a1b2c3 Начал делать логин
fixup d4e5f6 Поправил опечатку
fixup g7h8i9 Забыл запятую

# Результат: все три коммита объединятся в один с сообщением "Начал делать логин"
```

---

### `drop` — удалить коммит
```
pick a1b2c3 Первый коммит
drop d4e5f6 Второй коммит
```
**Что делает:** Полностью удаляет коммит из истории.

---

### `edit` — остановиться для редактирования
```
edit a1b2c3 Первый коммит
```
**Что делает:** Останавливает rebase на этом коммите, чтобы ты мог:
- Изменить файлы
- Сделать `git add`
- Сделать `git commit --amend`
- Продолжить: `git rebase --continue`

## 💡 Практический пример: Очистка истории

### Задача: Объединить несколько мелких коммитов в один

**Было:**
```
a1b2c3 Начал делать логин
d4e5f6 Поправил опечатку
g7h8i9 Забыл запятую
j9k0l1 Финальные правки
```

**Хочешь получить:**
```
a1b2c3 Реализация функционала Login
j9k0l1 Финальные правки
```

**Шаги:**

1. Запусти интерактивный rebase:
```bash
git rebase -i HEAD~4
```

2. В редакторе измени на:
```
reword a1b2c3 Начал делать логин
fixup d4e5f6 Поправил опечатку
fixup g7h8i9 Забыл запятую
pick j9k0l1 Финальные правки
```

3. Сохрани и закрой редактор.

4. Откроется редактор для изменения сообщения первого коммита. Напиши:
```
Реализация функционала Login
```

5. Сохрани и закрой.

**Результат:** Два чистых коммита вместо четырёх.

## ⚠️ Конфликты при Rebase

Если при rebase возникли конфликты:

```bash
# 1. Git остановится и покажет конфликт
# 2. Открой файлы с конфликтами и исправь их
# 3. Добавь исправленные файлы
git add .

# 4. Продолжи rebase
git rebase --continue

# Или отмени rebase
git rebase --abort
```

## 🚨 Важные правила безопасности

### 1. НЕ делай rebase на публичных ветках

```bash
# ❌ НИКОГДА НЕ ДЕЛАЙ:
git rebase origin/main
git push --force

# ✅ Делай rebase только на своей локальной ветке
git checkout feature-branch
git rebase main
git push --force-with-lease origin feature-branch
```

### 2. Используй `--force-with-lease` вместо `--force`

```bash
# ❌ Опасно:
git push --force

# ✅ Безопаснее:
git push --force-with-lease
```

**Почему:** `--force-with-lease` проверит, что удалённая ветка не изменилась с момента последнего fetch.

---

## 📋 Чек-лист: Когда использовать Rebase?

- [ ] Ты работаешь на своей feature-ветке (не на main/master)?
- [ ] Хочешь линейную историю без merge-коммитов?
- [ ] Нужно очистить историю (объединить мелкие коммиты)?
- [ ] Ветка ещё не запушена или ты один над ней работаешь?

**Если все "да" → используй rebase.**

---

## 🎓 Главное для Junior:

1. **Rebase** = способ сделать историю линейной и чистой.
2. **Interactive Rebase** (`-i`) = способ изменить последние N коммитов.
3. **Основные команды:** `pick`, `reword`, `squash`, `fixup`, `drop`.
4. **Безопасность:** НЕ делай rebase на публичных ветках (main/master).
5. **После rebase:** Используй `git push --force-with-lease`.

**Запомни:** Rebase меняет историю. Используй его только на своих ветках, которые ещё не запушены или над которыми работаешь только ты!
