# Git: Финальная чистка репозитория (Repo Cleanup)

> Формат: Senior учит Junior-а, как не оставить "грязных следов" в истории проекта перед тем, как скинуть ссылку работодателю.

---

## 1. 🧠 Зачем это нужно?

Когда лид открывает твой репо, он смотрит не только на `main.js`. Он смотрит на:
1. **Историю коммитов** (понятно ли, как рос проект?).
2. **Лишний мусор** (есть ли там `node_modules`, `.env` или забытые логи?).
3. **Безопасность** (не утекли ли ключи от базы?).

---

## 2. 🧹 Шаг 1: Удаление чувствительных данных

**Проблема:** Ты случайно запушил `.env` с паролями. Просто удалить файл и закоммитить — **не поможет**. Пароль останется в истории Git навсегда.

```bash
# Проверь, нет ли в истории секретов
git log -S "PASSWORD"
```

**Решение:** Используй `git-filter-repo` (рекомендуется) или BFG Repo-Cleaner.

```bash
# Удалить файл из всей истории Git полностью
git filter-repo --path .env --invert-paths
```

**На интервью:** "Как вы поступите, если случайно запушили API-ключ?"
— "Сначала я немедленно деактивирую/сменю ключ. Затем удалю его из истории Git с помощью `git filter-repo` или BFG. Просто удалить файл новым коммитом недостаточно."

---

## 3. 🏗️ Шаг 2: Причесывание истории (Squash)

**Проблема:** В истории висят коммиты типа "fix", "fix2", "try again", "added space". Это выглядит непрофессионально.

**Решение:** Интерактивный Rebase.

```bash
# Объединить последние 5 коммитов в один осмысленный
git rebase -i HEAD~5
```

В открывшемся редакторе:
```text
pick 1a2b3c4 Добавил логику авторизации
squash 2b3c4d5 fix
squash 3c4d5e6 fix typo
squash 4d5e6f7 added tests
```

**ASCII-схема (что происходит):**
```
  БЫЛО:  [A] --- [fix] --- [fix2] --- [docs] --- [B]
                               |
                               v
  СТАЛО: [A] ------------------------------------ [B*]
                (один чистый коммит "Feat: Auth system")
```

---

## 4. 📂 Шаг 3: Удаление "мусорных" веток

**Проблема:** 20 веток типа `test-feature`, `bugfix-1`, которые уже вмержены.

```bash
# Удалить вмерженные ветки локально
git branch --merged | grep -v "\*" | xargs -n 1 git branch -d

# Удалить ветку в облаке
git push origin --delete feature/old-task
```

---

## 5. 📝 Шаг 4: Проверка .gitignore

Убедись, что эти вещи **никогда** не попадут в репо:

    +--------------------------+---------------------------------------------+
    | Категория                | Что добавить в .gitignore                   |
    +--------------------------+---------------------------------------------+
    | Зависимости              | node_modules/, .venv/, venv/, target/       |
    | Секреты                  | .env, .env.local, *.pem, credentials.json   |
    | Логи                     | *.log, npm-debug.log*                       |
    | Специфика ОС             | .DS_Store (Mac), Thumbs.db (Windows)        |
    | Специфика IDE            | .idea/, .vscode/, *.swp                     |
    | Сборка                   | dist/, build/, out/                         |
    +--------------------------+---------------------------------------------+

## 6. 🛠️ Чек-лист финальной проверки

- [ ] **Никаких `console.log` или `TODO`** — удали или преврати в тикеты/задачи.
- [ ] **README.md** — есть скриншот, описание проекта, инструкция по запуску.
- [ ] **Лицензия** — добавь MIT или Apache (показывает, что ты думаешь о легальности).
- [ ] **Стиль кода** — прогони `npm run lint` или `black .` перед финальным пушем.
- [ ] **Git History** — нет коммитов "wip", всё красиво.

---

## Итого: "Золотой коммит"

Перед тем как отправить ссылку:
1. `git status` — чисто.
2. `git log --oneline` — только понятные сообщения.
3. `git remote -v` — ссылка ведет куда надо.

Твой репозиторий — это твоё лицо. Пусть оно будет чистым.
