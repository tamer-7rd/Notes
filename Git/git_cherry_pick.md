# Git Cherry-Pick (Выбор вишенки 🍒) — для Junior

Привет! Сегодня разберём команду `git cherry-pick`. Представь, что ты ешь торт, но хочешь взять с него только **одну вишенку**, не трогая остальной кусок.

В Git это работает так же: ты берёшь **один конкретный коммит** из другой ветки и переносишь его в свою, не сливая ветки целиком.

---

## 🎯 Что это простыми словами?

**Cherry-pick** — это копирование коммита (изменений) из одного места в другое.

Git берет изменения из выбранного коммита и применяет их к твоей текущей ветке как **новый коммит**.

---

## 🖼 Визуальная схема

Допустим, у тебя есть ветка `main` и ветка `feature`. В `feature` есть крутой фикс (коммит `C`), который срочно нужен в `main`.

**ДО Cherry-Pick:**

```
      A ─── B            (main)
             \
              C ─── D    (feature)
              ^
         (нужен этот!)
```

Мы делаем: `git cherry-pick C` (стоя на ветке `main`)

**ПОСЛЕ Cherry-Pick:**

```
      A ─── B ─── C'     (main)
             \
              C ─── D    (feature)
```

**Важно:** Коммит `C'` — это **копия**. У него будет другой хеш, но те же изменения. Оригинальный `C` остаётся на месте.

---

## 🛠 Как использовать?

### 1. Найди хеш коммита
Сначала посмотри историю в ветке, откуда хочешь взять коммит:

```bash
git log
# commit a1b2c3d... (Нужный нам коммит)
```

### 2. Перейди в свою ветку
В ту, **КУДА** хочешь вставить изменения:

```bash
git checkout main
```

### 3. Сделай Cherry-Pick

```bash
git cherry-pick a1b2c3d
```

Всё! Git возьмёт этот коммит и применит его.

---

## 🧩 Сценарии использования

### ✅ Сценарий 1: Хотфикс в feature-ветке
Ты делаешь фичу в ветке `feature/login`. В процессе ты заметил баг на сайте и исправил его. Но фича ещё не готова, а багфикс нужен в `main` уже сейчас.

**Решение:**
1. Закоммить багфикс в `feature/login`.
2. Перейди в `main`.
3. Сделай `git cherry-pick <hash-багфикса>`.
4. Запушь `main`.

### ✅ Сценарий 2: Восстановление потерянного коммита
Ты случайно удалил ветку, но помнишь хеш важного коммита (или нашел его через `git reflog`).

**Решение:**
1. Создай новую ветку.
2. Сделай `git cherry-pick <hash>`.

### ✅ Сценарий 3: Перенос коммита в правильную ветку
Ты случайно закоммитил в `main`, а надо было в `feature`.

**Решение:**
1. Создай ветку `feature` (если нет).
2. В `feature`: сделай `git cherry-pick <hash-из-main>`.
3. В `main`: удали этот коммит (через `git reset --hard HEAD~1`).

---

## ⚠️ Возможные проблемы (Конфликты)

Как и при мерже, могут возникнуть конфликты.

Если Git скажет `CONFLICT`:
1. Открой файлы и реши конфликты вручную.
2. Добавь файлы: `git add .`
3. Продолжи: `git cherry-pick --continue`

Если передумал: `git cherry-pick --abort` (отмена).

---

## ✅ Плюсы и ❌ Минусы

| Плюсы | Минусы |
|-------|--------|
| Точечный перенос изменений | Меняется хеш коммита (это копия) |
| Не нужно мержить всю ветку | Можно запутаться, если черри-пикать много |
| Спасает при ошибках (коммит не туда) | При будущем мерже может быть конфликт (Git увидит "одинаковые" изменения) |

---

## 📋 Чек-лист: Когда использовать Cherry-Pick?

- [ ] Тебе нужен **только один** коммит из другой ветки?
- [ ] Ты не хочешь мержить **всю** ветку?
- [ ] Ты случайно закоммитил не туда и хочешь перенести?

**Если "да" — используй Cherry-Pick.**

---

## 🎓 Главное для Junior:

1. **Cherry-pick копирует коммит.** Он не переносит его физически, а создаёт копию.
2. **Команда:** `git cherry-pick <hash>`.
3. **Используй редко.** Если тебе нужно перенести 10 коммитов — лучше сделай Merge или Rebase. Cherry-pick — это "хирургический инструмент" для 1-2 коммитов.
