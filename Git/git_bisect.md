# Git Bisect: Как найти иголку в стоге сена

Представь ситуацию: вчера твой код работал идеально. Ты ушел спать, а сегодня утром проект сломан. За это время ты или твоя команда сделали 20, 50 или 100 коммитов.

**Вопрос:** Какой именно коммит всё сломал?

Руками проверять каждый коммит — долго и мучительно. Здесь на помощь приходит `git bisect`.

---

## 1. Что такое Git Bisect?

`git bisect` — это инструмент, который использует **бинарный поиск** (метод деления пополам), чтобы найти коммит, который внес ошибку (баг).

### Аналогия с игрой "Угадай число"
Представь, что я загадал число от 1 до 100.
Ты спрашиваешь: "50?"
Я говорю: "Меньше".
Ты сразу отбрасываешь числа 50-100.
Ты спрашиваешь: "25?"
И так далее.

`git bisect` делает то же самое с историей коммитов. Он делит историю пополам, предлагает тебе проверить середину, и отсекает половину вариантов.

---

## 2. Как это работает (Пошаговый алгоритм)

### Шаг 0: Подготовка
Убедись, что у тебя есть "чистая" рабочая директория (нет незакоммиченных изменений), иначе `bisect` может не запуститься.

### Шаг 1: Запуск
Говорим гиту, что начинаем охоту:

```bash
git bisect start
```

### Шаг 2: Обозначаем "плохой" коммит
Обычно "плохой" — это текущее состояние, где баг воспроизводится.

```bash
git bisect bad
```
*(Если не указать хэш, Git считает текущий коммит "плохим")*

### Шаг 3: Обозначаем "хороший" коммит
Тебе нужно найти в истории любой старый коммит, где всё точно работало. Найди его хэш через `git log` (например, `a1b2c3d`).

```bash
git bisect good a1b2c3d
```

### Шаг 4: Процесс поиска (Магия)
Как только ты ввел "хороший" и "плохой" коммиты, Git автоматически переключит твой проект на коммит ровно посередине между ними.

Твоя задача сейчас — **проверить, есть ли баг**:
1. Запусти проект.
2. Попробуй воспроизвести ошибку.

**Вариант А: Ошибка есть**
Значит, "плохой" коммит где-то в прошлом (между текущим и старым "хорошим").
Говорим гиту:
```bash
git bisect bad
```

**Вариант Б: Ошибки нет (всё работает)**
Значит, "плохой" коммит случился позже (в будущем относительно текущего момента).
Говорим гиту:
```bash
git bisect good
```

Git снова переключит тебя на середину оставшегося диапазона. Повторяй этот шаг, пока Git не скажет:

> **a1b2c3d is the first bad commit**

Поздравляю, ты нашел виновника!

### Шаг 5: Завершение
Когда ты нашел проблемный коммит, нужно вернуться в исходное состояние (на ветку, где ты был в начале):

```bash
git bisect reset
```

---

## 3. Шпаргалка (Быстрый старт)

```bash
# 1. Начать
git bisect start

# 2. Текущая версия сломана
git bisect bad

# 3. Версия a1b2c3d работала (найти хэш через git log)
git bisect good a1b2c3d

# ... Git переключает вас на середину ...

# 4. Проверяем код.
# Если работает:
git bisect good
# Если сломано:
git bisect bad

# ... Повторяем до нахождения ...

# 5. Закончить и вернуться обратно
git bisect reset
```

---

## 4. Продвинутый уровень: Автоматизация

Если у тебя есть автотест (скрипт), который падает (exit code 1) при баге и проходит (exit code 0), когда всё ок, ты можешь заставить Git искать ошибку за тебя!

```bash
git bisect start
git bisect bad
git bisect good <старый-хэш>

# Запустить автопоиск
git bisect run npm test
# или
git bisect run python manage.py test
```

Git сам будет переключать коммиты, запускать команду и помечать bad/good, пока не найдет виновника. Это выглядит очень круто со стороны! 😎
