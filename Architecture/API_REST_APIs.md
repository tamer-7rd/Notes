# API и REST API — для Junior

## 🎯 Что такое API простыми словами?

**API (Application Programming Interface)** = "Программный интерфейс".

Это набор правил, по которым программы общаются друг с другом. API — это язык общения программ, а не людей.

**Примеры из жизни:**
- Ты пишешь `import os` в Python → библиотека `os` даёт тебе API для работы с файлами.
- Ты делаешь запрос к погодному сервису → их API возвращает тебе JSON с температурой.
- Твой React-фронт общается с Flask-бэком через HTTP → это веб-API.

---

## 🌐 Что такое REST API?

**REST (Representational State Transfer)** = стиль построения веб-API, набор правил.

REST — это не технология, а **идеология**: как правильно строить API, чтобы всем было понятно.

**Важно:** REST используется не только для общения фронта и бэка. Это правила для **любых** клиент-серверных взаимодействий:
- Фронтенд ↔ Бэкенд
- Мобильное приложение ↔ Бэкенд
- Микросервис ↔ Микросервис
- Внешний сервис ↔ Твой API
- Бот/CLI ↔ API

**Суть:** REST — это универсальные правила построения API для любых клиентов и серверов.

### Основные правила REST:

#### 1. HTTP-методы по назначению
```
GET    → получить данные (читать)
POST   → создать данные
PUT    → обновить данные (полностью)
PATCH  → обновить данные (частично)
DELETE → удалить данные
```

#### 2. Ресурсные URL (понятные адреса)
```
GET    /api/users          → список всех пользователей
GET    /api/users/5        → пользователь с ID=5
POST   /api/users          → создать нового пользователя
PUT    /api/users/5        → обновить пользователя №5
DELETE /api/users/5        → удалить пользователя №5
```

#### 3. Ответы в формате JSON (не HTML!)
```json
{
  "id": 5,
  "name": "Tamerlan",
  "email": "tamerlan@example.com"
}
```

#### 4. Правильные статус-коды HTTP
```
200 OK              → всё хорошо, данные вернулись
201 Created         → ресурс успешно создан
400 Bad Request     → ошибка клиента (неправильный запрос)
404 Not Found       → ресурс не найден
500 Internal Error  → ошибка сервера
```

#### 5. Stateless (без состояния)
Каждый запрос самодостаточен. Сервер не помнит предыдущие запросы.

## 📦 Что такое JSON?

**JSON (JavaScript Object Notation)** = текстовый формат для обмена данными.

**Простыми словами:** JSON — это способ превратить объект (dict в Python, object в JS) в строку и обратно.

**Важно:** JSON выглядит как объект (с фигурными скобками, кавычками), но на самом деле это просто **текстовая строка** в специальном формате. Это не объект, это его "pretty-форма" (красивое представление) в виде строки.

### Пример:
```json
{
  "user": "Tamerlan",
  "wpm": 92,
  "accuracy": 0.97
}
```

**Как работать с JSON:**
- В Python: `json.dumps()` (объект → строка), `json.loads()` (строка → объект).
- В JavaScript: `JSON.stringify()` (объект → строка), `JSON.parse()` (строка → объект).

**Зачем:** JSON — это мост между сервером (Python dict) и клиентом (JS object). Они оба понимают этот формат.

---

### Где передаётся JSON? (URL vs Body)

**Важно понять:** JSON передаётся в **теле запроса (body)**, а не в URL.

#### GET запрос (данные в URL — видно в браузере):
```javascript
// Простые данные в адресной строке
fetch('/api/users?name=Tamerlan&age=25')
```
**Видно:** Всё в адресной строке браузера. JSON здесь не нужен.

#### POST/PUT/PATCH запрос (данные в body — не видно в URL):
```javascript
// Сложные данные в теле запроса
fetch('/api/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'  // Говорим, что отправляем JSON
  },
  body: JSON.stringify({  // ← Вот тут JSON-строка в body!
    name: "Tamerlan",
    age: 25,
    city: "Moscow"
  })
})
```
**Не видно:** В адресной строке только `/api/users`, а данные идут отдельно в body.

**Структура HTTP-запроса:**
```
POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json

{"name": "Tamerlan", "age": 25}  ← Это тело запроса (body)
```

**Где увидеть body:**
- В коде: параметр `body` в `fetch()` или `axios.post()`.
- В браузере: DevTools (F12) → Network → выбери запрос → вкладка **Payload** или **Request**.

**Почему body не видно в URL?**
- Безопасность: пароли не попадают в адресную строку.
- Удобство: можно отправлять большие объёмы данных и файлы.

**Аналогия:** GET = письмо с адресом на конверте (всё видно). POST = письмо в конверте (адрес снаружи, содержимое внутри).

## 🏗️ Что такое API-слой?

**API-слой** = часть приложения, которая отвечает за обмен данными между фронтом и бэком.

### На фронтенде (React/Next.js):
Отдельные файлы с функциями для запросов:
```javascript
// api/users.js
import axios from 'axios';

export const getUsers = () => axios.get("/api/users");
export const getUserById = (id) => axios.get(`/api/users/${id}`);
export const createUser = (data) => axios.post("/api/users", data);
```

### На бэкенде (Flask/Express):
Маршруты `/api/...`, которые возвращают JSON:
```python
# Flask пример
@app.route('/api/users', methods=['GET'])
def get_users():
    users = user_service.get_all_users()
    return jsonify(users)  # Возвращаем JSON, не HTML!
```

**Архитектура бэка (обычно):**
```
Controller → принимает HTTP-запрос
    ↓
Service → бизнес-логика
    ↓
Repository → работа с базой данных
```

## ❓ Когда нужен REST/API-слой?

REST **не обязателен**, но нужен если:

- ✅ Нужен "живой" интерфейс (AJAX) — обновление без перезагрузки страницы.
- ✅ Планируется фронт на React/Vue/Next.js.
- ✅ Будет мобильное приложение или боты (Telegram, Discord).
- ✅ Нужна "чистая" архитектура (данные отдельно от представления).

**Можно гибрид:** Оставить HTML-страницы (`/contact`), а JSON-эндпоинты добавить точечно (`/api/contact`).

---

## 📋 Чек-лист: Как понять, что ты делаешь REST API правильно?

- [ ] Используешь правильные HTTP-методы (GET для чтения, POST для создания).
- [ ] URL понятные и ресурсные (`/api/users/5`, а не `/api/getUserById?id=5`).
- [ ] Возвращаешь JSON, а не HTML.
- [ ] Используешь правильные статус-коды (200, 201, 400, 404, 500).
- [ ] Каждый запрос самодостаточен (не зависит от предыдущих).

---

## 🎓 Главное для Junior:

1. **API** = способ общения программ друг с другом.
2. **REST API** = API по единым правилам (методы, URL, JSON, статус-коды).
3. **API-слой** = место в коде, где фронт и бэк обмениваются данными.
4. **JSON** = формат данных, который понимают и Python, и JavaScript.

**Запомни:** HTML-маршруты (`/contact`) нужны человеку (браузер показывает страницу). API-маршруты (`/api/contact`) нужны программе (возвращают данные для обработки).
