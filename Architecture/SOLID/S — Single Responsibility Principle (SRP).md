# S — Single Responsibility Principle (SRP)

---

## 🔑 Суть принципа

Каждый модуль, класс или функция должна иметь только одну причину для изменения. (главный маркер в этой фразе при решениях)

Переводя на язык практики:
- один файл/компонент/сервис делает что-то одно;
- если он начинает брать на себя лишние обязанности → код становится хрупким и трудным для поддержки.

---

## 🧠 Углубление (для собеседований)

Роберт Мартин (автор принципа) уточняет: **«Модуль должен отвечать за одного и только одного актора»**.

**Пример проблемы:**
Представь класс `Employee`, у которого есть методы:
1. `calculatePay()` — логика для **бухгалтерии**.
2. `reportHours()` — логика для **отдела кадров**.

Если эти методы лежат в одном классе и используют общие вспомогательные функции, то изменение требований бухгалтерии может случайно сломать отчеты для кадров.

✅ **Суть:** Разделяй код не только по тому, *что* он делает, но и *для кого* (кто заказчик изменений).

---

## 🎯 Примеры из фронтенда (React)

### 1. ❌ Плохо:

```jsx
function UserProfile() {
  // отвечает за загрузку данных
  const [user, setUser] = useState(null);
  useEffect(() => {
    fetch("/api/user")
      .then(res => res.json())
      .then(data => setUser(data));
  }, []);

  // отвечает за отображение
  if (!user) return <p>Loading...</p>;
  return (
    <div>
      <h1>{user.name}</h1>
      <button onClick={() => alert("Followed!")}>Follow</button>
    </div>
  );
}
```

Тут компонент и фетчит данные, и отрисовывает UI, и даже обрабатывает действия. Нарушение SRP.

### 2. ✅ Хорошо:

- `UserService.js` → отдельный модуль для запроса к API.  
- `UserProfile.jsx` → отвечает только за отрисовку.  
- `FollowButton.jsx` → отдельная логика для кнопки.

## 🎯 Примеры из бэкенда (Node.js/Nest)

### 1. ❌ Плохо:

```js
// userController.js
app.post("/user", async (req, res) => {
  // валидация
  if (!req.body.email.includes("@")) return res.status(400).send("Invalid email");

  // бизнес-логика
  const hashed = await bcrypt.hash(req.body.password, 10);
  const user = { email: req.body.email, password: hashed };

  // сохранение
  db.users.insert(user);

  // ответ
  res.json(user);
});
```

Тут контроллер и валидирует, и считает хэши, и сохраняет в БД. Всё намешано.

### 2. ✅ Хорошо:

- `UserController` → только принимает запрос и отдаёт ответ.  
- `UserService` → бизнес-логика (хэши, правила).  
- `UserRepository` → доступ к БД.  

---

## ⚡ Почему это важно для тебя

- Код становится чище: легко читать и дорабатывать.  
- Ошибки проще находить (сразу видно, в каком слое проблема).  
- Легко тестировать (можно тестить отдельно сервис без БД или UI).  
- В будущем — пригодится на собеседованиях, потому что SRP любят спрашивать.
